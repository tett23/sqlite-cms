# 0014 Rust 依存の更新と削減

## 状態

採用。
0001 と 0006 の「frontmatter を serde_yaml で解釈する」、0001 の「DB のファイル名のハッシュに SHA-256 を使う」を置き換える。
0048 で、文字列のリスト（`tags`）を読めるようにした。

## 決定

`cli/` の Rust の依存をすべて最新にし、自前で簡単に書けるものは実装して依存から外す（ADR 0013 と同じ方針）。

### 自前の実装に置き換えたもの

- **base64**：アセットのハッシュとアップロードに使う標準形式への変換と、JWT の本文を読むための URL-safe 形式（パディングの有無を問わない）の読み取りだけを `base64.rs` に実装する。RFC 4648 の検証用の値でテストする。
- **mime_guess**：配信するファイルの拡張子と MIME の対応表を `mime.rs` に持つ。拡張子の大文字と小文字は区別しない。表にない拡張子は、アップロードでは `application/null`（wrangler と同じく、Content-Type を付けない指定）、`serve` では `application/octet-stream` とする。
- **serde_yaml**：crates.io で非推奨（deprecated）になっている。frontmatter は平らな「キー: 値」なので、その範囲だけを読むパーサを `frontmatter.rs` に実装する。
  - 値はクォートなし、ダブルクォート（`\"`、`\\`、`\/`、`\n`、`\t`、`\r`、`\uXXXX` のエスケープ）、シングルクォート（`''` で `'`）のいずれか。
  - 行頭の `#` と、値の後ろの ` #` はコメント。空、`~`、`null` は値なしとする。
  - 複数行の値（`|`、`>`）、フローのリストと対応（`[`、`{`）、アンカーとタグ（`&`、`*`、`!`）、字下げした行、重複したキーは、何行目の何が問題かを示してエラーにする。黙って誤読しないためである。
  - 値はすべて文字列として読む。YAML では数値や真偽値になる値（`title: 2026` など）も、文字列として受け付ける。
- **sha2**：DB のファイル名のハッシュにだけ使っていた。すでに依存している blake3 に替える（先頭 16 桁）。ファイル名は内容から決まる名前でしかないので、アルゴリズムを変えても互換の問題はない。
- **tempfile**（テスト用）：一時ディレクトリを作り、破棄するときに消すだけの `testutil.rs` に置き換える。結合テストからは `#[path]` で同じファイルを読み込む。

### 残したもの

| クレート | 残す理由 |
|---|---|
| anyhow | エラーに文脈を付ける仕組みを全体で使っている。依存を持たない小さなクレートで、置き換えても得るものが少ない |
| serde、serde_json | Cloudflare API の JSON を堅く読み書きする部分は、簡単には書けない |
| toml | `site.toml` は表（`[license]`、`[deploy]`）を持ち、TOML のパーサは簡単ではない |
| rusqlite | SQLite 本体（同梱してビルドする） |
| ureq | TLS 付きの HTTP クライアント |
| blake3 | Cloudflare のアセットのハッシュと互換にするため |

### 更新

- rusqlite を 0.37 から 0.40 に上げる。使っている API に変更はなかった。
- ureq の既定の機能のうち `gzip` を外し、`rustls` だけを有効にする。Cloudflare API の応答は小さな JSON で、圧縮の展開は要らない。
- ほかのクレートは同じメジャーの最新にする（`cargo update`）。

### 効果

- Cargo.lock 上のクレートが 101 個から 83 個になった。rusqlite 0.40 は wasm32 向けにだけ使う依存（wasm-bindgen など）を持ち込むが、手元のビルドには含まれない。手元でビルドされるのは 57 個である。
- release のバイナリが 5.6 MB から 5.2 MB になった。

## 実装しないこと

- YAML の完全な実装。frontmatter で複数行の値が必要になったら、この ADR を置き換える形で方針を決め直す。
- 改行コード CRLF の frontmatter。区切りの `---` の判定が LF 前提のまま（従来どおり）。

## テスト設計

- base64：RFC 4648 の検証用の値（変換と、パディングありとなしの読み取り）、URL-safe の文字、不正な文字と長さ、全バイト値の往復。
- MIME：主な拡張子、大文字と小文字、未知の拡張子、`text/*` がすべて `charset=utf-8` を持つこと。
- frontmatter：クォートなしの値（途中のコロン、値の後ろのコメント、`#` を含む値）、ダブルクォートのエスケープ、シングルクォート、null の書き方、空行とコメント、対応しない書き方のエラー、不正な行、クォートの閉じ忘れと不正なエスケープ。
- 既存のテスト（記事の検証、DB の構築、組み立て、公開の手順、結合テスト）が、置き換え後もそのまま通ること。

## トレードオフ

- frontmatter で YAML の一部が使えなくなる。以前は serde_yaml が受け付けていた複数行の値やリストが、エラーになる。現在の記事と項目（`title`、`date`、`description`、`updated`）は、すべて 1 行の文字列で足りる。
- 自前の実装は、その分のテストと保守を自分で持つことになる。どれも仕様が小さく固定されたもの（RFC 4648、拡張子の表、1 行の「キー: 値」）に限っている。
