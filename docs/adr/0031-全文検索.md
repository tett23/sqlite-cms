# 0031 全文検索

## 状態

採用。
仕様書の未決事項「全文検索（FTS5）の導入時期」に答える。
0041 で、検索のページ以外のヘッダに検索ボックスを置いた。
0047 で、FTS4 の索引を使わず、すべての文書を JavaScript で確かめて探すことにした（結果は変わらない）。
0048 で、`#` で始まる語でタグを探せるようにした。

## 決定

サイトに全文検索を入れる。
ヘッダに「検索」を置き、`/search` で post、article、自己紹介の題名と本文を探せるようにする。

### FTS5 ではなく FTS4 を使う

SPA が使う sql.js の既定のビルドには FTS5 が入っていない（`no such module: fts5`）。FTS4 は入っている。
FTS5 を使うには sql.js を自前でビルドし直す必要があり、Emscripten の環境と、ビルドの成果物の管理を抱えることになる。
記事の数が少ない個人のサイトでは、FTS4 で足りるので、FTS4 を使う。

### 日本語の区切り方

FTS4 の分かち書き（`simple`、`unicode61`）は、空白で区切らない日本語を語に分けられない。
FTS5 の `trigram` も FTS4 にはない。
そこで、索引に入れる前に、こちらで文字列を語に分ける。

- 文字列を正規化する（NFKC で全角の英数字を半角にし、小文字にする）。
- 英数字などの文字（`\p{L}`、`\p{N}`）が続く部分は、一つの語にする。
- ひらがな、カタカナ、漢字が続く部分は、2 文字ずつ重ねて区切る（「記事置き場」→「記事」「事置」「置き」「き場」）。
- それ以外の文字（記号、空白）は区切りにする。

検索する言葉も同じように分け、語の並びを FTS4 の句（`"使い い方"`）にする。句は語が隣り合うものにだけ一致するので、「置き方」が「置き場」と「使い方」にまたがって一致することはない。
英数字の語で終わる句は前方一致（`"sqlite cms*"`）にし、打ちかけの言葉でも探せるようにする。
空白で区切った言葉は、すべてを含むもの（AND）を探す。

1 文字の日本語（「字」など）は 2 文字ずつの語にならず、索引で探せない。
そこで、索引で候補を絞った後に、元の文字列（正規化したもの）に言葉がすべて含まれることを確かめる。
1 文字の日本語だけの検索では、索引を使わずに全文書を確かめる。記事の数が少ないので速い。

### 索引を作る時期と場所

索引は DB には入れず、最初に検索したときにブラウザで作る（一時的な表 `temp.search_documents` と `temp.search_index`）。

- DB を大きくしない。2 文字ずつの語の索引は本文より大きくなり、検索を使わない読み手にも読み込ませることになる。
- 記事の数が少ないので、作るのに時間はかからない。
- 一時的な表なので、DB のファイルは変わらない。

### 探すもの

- post、article（要約を含む）、自己紹介（`pages` の `about`）の題名と本文。URL のないほかの page は探さない。
- 本文は Markdown の記号を大まかに取り除いてから探す（見出しの `#`、強調、リンクの URL、HTML のタグ、コードブロックのフェンスなど）。コードブロックの中身は探す。

### 結果

- 題名に言葉を多く含むものを先に、あとは新しい順に並べる。
- 題名、種別（ブログ、記事、ページ）、日付と、本文の最初に言葉が現れるあたりの抜き出し（約 110 文字）を出し、言葉の部分を `<mark>` で示す。
- 件数は `role="status"` で読み上げる。
- 探す言葉は、打つたびに結果を出し、URL の `?q=` に残す（`history.replaceState`）。`/search?q=言葉` の URL で結果を開ける。

## 実装しないこと

- FTS5（sql.js を自前でビルドし直すこと）。
- 検索の結果の順位付け（BM25 など）。記事が増えて並びに困ったら考える。
- 表記の揺れ（ひらがなとカタカナ、送り仮名）の吸収。
- ヘッダに検索の入力欄を置くこと。ヘッダが狭いので、検索のページへの案内だけにする。

## テスト設計

- 語の分け方：英数字、日本語の 2 文字ずつの区切り、全角の英数字と大文字。
- 検索式：句、前方一致、1 文字の日本語（式にしない）、記号だけの言葉。
- Markdown の記号の取り除き方。
- 検索：日本語、英数字、全角の英数字、前方一致、複数の言葉、題名を先にする並び、1 文字の日本語、隣り合わない並びが一致しないこと、コードブロックの中、自己紹介と URL のないページ、結果のパスと抜き出し、空の言葉。
- 抜き出し：言葉のあたりを切り出して印を付けること、言葉がなければ先頭から出すこと。

ブラウザでは、`/search?q=組版` で開いて結果と印を、入力に合わせて結果と URL が変わることを確かめた。
Lighthouse の計測するページに `/search?q=記事` を加え、アクセシビリティとベストプラクティスが 100 点だった。

## トレードオフ

- 2 文字ずつの区切りは、意味の区切りを考えないので、「京都」で「東京都」も見つかる。
- 最初の検索で索引を作る分だけ、最初の結果が少し遅れる。
- Markdown の記号の取り除き方は大まかで、HTML の中の文字（ルビの読みなど）も本文として探す。
