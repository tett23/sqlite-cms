# 0048 ハッシュタグ

## 状態

提案。
0014 の「frontmatter のリストはエラーにする」を、文字列のリストを読めるように改める。
0031 の検索に、タグで探す書き方を加える。

## 決定

post と article にタグを付けられるようにし、記事のページに表示して、検索で使えるようにする。

### 書き方

frontmatter の `tags` に、タグのリストを書く。

```yaml
tags: [組版, SQLite]
```

複数行の形でも書ける。

```yaml
tags:
  - 組版
  - SQLite
```

- 先頭の `#`（全角の `＃` も）は外して読む。ただし YAML では `#` から後ろが注釈になるので、`#` を付けて書くときは `"#組版"` のようにクォートで囲む。`tags: [#組版]` と書いたときは、黙ってタグを落とさず、直し方を添えたエラーにする。
- タグに空白と `#` は使えない。検索では空白で語を区切り、`#` でタグを表すからである。
- 同じタグを二度書いたら、一つにまとめる。
- `tags: 組版` のようにリストでない書き方は、リストで書くよう知らせるエラーにする。`組版, SQLite` を一つのタグとして読んでしまわないためである。
- page にはタグを付けない（書いても読まない）。
- `new` が作る post と article の雛形に、`tags: []` を入れる。書く場所がわかるようにするためである。

YAML のリストにしたのは、frontmatter を読むほかの道具（エディタ、静的サイトジェネレータ）と同じ書き方だからである。
`tags: #組版 #SQLite` のような書き方は、YAML では値が注釈になって消えるので採らない。

### frontmatter の読み手

自前の読み手（0014）に、文字列のリストを足す。値は、値なし、文字列、リストのどれかになる。

- 一行の形（`[a, "b, c", 'd']`）：値は `,` で区切り、そのまま書くか、クォートで囲む。最後の `,` は許す。入れ子は読まない。
- 複数行の形：値のないキーの次の行から、`- 値` の行が続く間を読む。
- リストを書けるのは `tags` だけにする。ほかのキーにリストを書いたら、値なしとして読まずにエラーにする。

### DB

タグは `tags` の表に入れる（マイグレーション 0008）。

```sql
CREATE TABLE tags (
  kind     TEXT NOT NULL,     -- post か article
  slug     TEXT NOT NULL,
  position INTEGER NOT NULL,  -- 書いた順（0 から）
  tag      TEXT NOT NULL,     -- 先頭の # は付けない
  PRIMARY KEY (kind, slug, position)
);
```

post と article の表に列を足さなかったのは、一つの記事がいくつものタグを持つからである。
SPA の自前の DB の読み手（0047）は、この表の行を読み、記事ごとに書いた順に並べる。
タグの表のない DB では、タグなしとして扱う。

### 表示

- post と article のページで、日付の下に `#組版 #SQLite` のように並べる。
- 検索の結果でも、題名の下に並べる。
- タグはリンクで、押すとそのタグでの検索（`/search?q=%23組版`）に移る。
- タグの並びには、読み上げ用の名前（「タグ」）を付ける。
- タグのリンクには上下に余白を付け、押せる範囲を 24 px 以上にする。余白がないと、狭い画面の検索の結果で、Lighthouse のユーザー補助（タップする対象の大きさと間隔）が 96 点になった。

トップページと一覧（`/archive`）には出さない。一覧は題名と日付を並べるもので、タグを足すと行が増えるからである。

### 検索

検索する言葉のうち、`#` で始まる語は、タグとして探す。

- `#組版` は、「組版」のタグの付いた記事だけに一致する。本文に「組版」とあるだけの記事には一致しない。
- タグは、全体が一致するものだけを探す（`#組` は「組版」に一致しない）。大文字と小文字、全角と半角は区別しない（0031 の正規化と同じ）。全角の `＃` も `#` として扱う。
- ほかの語やタグと組み合わせると、すべてを満たすものを探す（`#組版 #SQLite ルビ`）。
- `#` のない語は、題名と本文に加えて、タグからも探す。
- `#` だけの語は無視する。`C#入門` のように途中に `#` がある語は、今までどおり語として探す。

ヘッダの検索ボックスの候補（0042）も同じ検索を使うので、`#` で始まる語でタグを探せる。

### RSS

RSS のフィード（0033）の各項目に、タグを `category` として載せる。

## 実装しないこと

- タグの一覧のページと、タグごとの記事の数。
- タグごとのページ（`/tags/組版`）。検索のページ（`/search?q=%23組版`）がその役を果たし、URL として残せる。
- 本文の中に書いた `#タグ` をタグとして拾うこと。見出しの `#` や、`C#` のような語と区別できない。
- タグの入力の補完。
- サイトマップにタグの検索のページを載せること（0037 と同じく、検索のページは載せない）。

## テスト設計

- frontmatter：一行のリスト（空白、クォート、`,` を含む値、最後の `,`、空のリスト、注釈）、複数行のリスト、値のないキー、壊れたリスト（閉じていない、空の値、入れ子、`,` のない並び、閉じていないクォート）、`#` で始まる値の知らせ方。
- 記事：タグを読み、先頭の `#` を外し、重なりをまとめること。タグがなければ空。リストでない書き方、空白や `#` を含むタグ、空のタグはエラー。`tags` のほかのキーのリストはエラー。
- DB：タグを書いた順に入れること。SPA の読み手の前提（0047）を守ること（既存のテスト）。
- RSS：タグを `category` として載せ、文字をエスケープすること。
- 雛形：post と article に `tags: []` を入れ、page には入れないこと。
- SPA の DB：記事と post のタグを書いた順に返すこと。種類が違えば別のタグ。タグの表のない DB では空。
- 検索：`#` で始まる語の分け方（全角、`#` だけ、途中の `#`）。タグの付いた記事だけに一致すること。全体の一致、大文字と小文字、タグと語の組み合わせ、`#` のない語がタグからも探すこと、結果にタグが付くこと、タグのリンクの URL。
- E2E：記事のページにタグが出ること。タグを押すとページを読み直さずに検索に移り、タグの付いた記事だけが出ること（本文に同じ語のある記事は出ない）。ヘッダの検索ボックスで `#` で始まる語の候補が出ること。

## トレードオフ

- frontmatter の読み手が、リストの分だけ大きくなる。
- タグの書き方の揺れ（「SQLite」と「sqlite」）は、検索では同じに扱うが、表示は書いたままである。そろえるのは書き手に任せる。
- タグの一覧がないので、どんなタグがあるかは記事から知るしかない。
