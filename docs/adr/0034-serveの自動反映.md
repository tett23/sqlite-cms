# 0034 serve の自動反映

## 状態

提案（利用者の確認待ち）。
仕様書の未決事項「`serve` での記事の変更の自動反映（現在は再起動が要る）」に答える。

## 決定

`serve` は記事の変更を見つけて組み立て直し、開いているブラウザを読み込み直させる。
`--no-reload` で止められる。

### 変更の見つけ方

- 0.5 秒ごとに、`site.toml` と `content/` の中のファイルの一覧、大きさ、更新時刻から指紋（ハッシュ）を作り、前と比べる（`cli/src/watch.rs`）。
- OS の変更の通知（FSEvents、inotify）は使わない。依存（notify など）を足さずに済み、記事リポジトリのファイルは少ないので、調べるのは速い。
- `.sqlite-cms-cache/` や `.env` など、`content/` の外の変更は数えない。

### 組み立て直し

- 変更を見つけたら、起動のときと同じく一式を組み立て直し（DB、画像、リンクカードの画像、SPA）、配信する中身を入れ替える。
- 組み立てに失敗したら（frontmatter の書き誤りなど）、エラーを表示し、前の中身のまま配信を続ける。直せば、次の変更で反映する。
- `base_path` は起動のときに決めた値を使い続ける。変わったら、起動し直すよう警告する。
- リンクカードの画像は、保存した結果を使い、新しい URL だけを取得する（ADR 0028）。

### ブラウザの読み込み直し

- Server-Sent Events の口（`<base_path>__sqlite-cms/events`）を置く。組み立て直すたびに `event: reload` を送り、15 秒ごとに接続を保つための注釈を送る。
- `serve` のときだけ、`index.html` と `404.html` の `</body>` の前に、`EventSource` で `reload` を受けたら `location.reload()` する短いスクリプトを入れる。`build` と `deploy` の出力には入れない。
- 読み込み直すと、SPA はマニフェストから新しい DB を読む（DB のファイル名は中身で変わる）。
- WebSocket は使わない。サーバーからブラウザへの一方向の知らせで足り、HTTP の応答として書けるので、自前の HTTP サーバーに収まる。
- `serve` を止めて起動し直すと、`EventSource` がつなぎ直す。つなぎ直しただけでは読み込み直さない。

### 表示

- 起動のときに「記事を変えると自動で反映します」と表示する。反映したら「変更を反映しました」と表示する。
- 表示の出力先が閉じていても（パイプなど）、監視を止めない。Rust の `println!` は書けないと止まってしまうので、書けなくても無視する形で書く。

### `--no-reload`

監視とスクリプトを止める。
Lighthouse の計測（ADR 0019）では、開いたままの `EventSource` の接続が計測の終わりを待たせるおそれがあるので、`--no-reload` を付けて起動する。

## 実装しないこと

- ページを読み込み直さずに、DB だけを取り換えること。表示中の状態（スクロールの位置など）は失う。
- 変更のあったページだけを描き直すこと。
- `base_path` の変更の反映。
- OS の変更の通知を使うこと。

## テスト設計

- 指紋：ファイルを足す、変える、消すと変わり、元に戻せば同じになること。`content/` の外の変更で変わらないこと。
- 配信の状態：中身を入れ替えると、待っている接続が起き、新しい中身を返すこと。
- スクリプト：`</body>` の前に入り、`base_path` の下の口を指すこと。`index.html` と `404.html` の両方に入ること。
- 結合テスト：起動した `serve` の口に接続し、記事を足すと `event: reload` が届き、DB が変わること。書き誤りのある記事を足しても前の DB のまま配信し、直すと反映すること。`--no-reload` ではスクリプトが入らないこと。

ブラウザでは、記事の題名を書き換えると、開いていたページが読み込み直され、新しい題名が出ることを確かめた。

## トレードオフ

- 0.5 秒ごとにファイルを調べるので、変更から反映までに最大で 0.5 秒と組み立ての時間がかかる。
- 大きな記事リポジトリでは、調べるたびにファイルの一覧を読む分の負荷がかかる。
- 組み立て直すたびに、DB だけでなく一式を組み立てる。
