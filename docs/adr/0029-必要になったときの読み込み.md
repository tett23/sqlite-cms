# 0029 必要になったときの読み込み

## 状態

採用。
0017 の「アプリの起動と同時に、DB の取得と並行して Shiki を読み込み始める」を改める。
0017 で実装しないことにした「記事にコードブロックがあるときだけ Shiki を読み込むこと」を実装する。
0038 で、読み込みを始めるときを「画面の近くに来て、本文を描いた後に手が空いたとき」に改めた。

## 決定

本体とは別のチャンクにしている大きなライブラリ（Shiki、KaTeX、mermaid）は、それを使う部品が表示されたときに初めて読み込む。
読み込むまでは生のテキストを表示し、読み込み終わったら描き直す。

| ライブラリ | 読み込みを始めるとき | 読み込むまでの表示 |
|---|---|---|
| Shiki | 色を付ける言語のコードブロックが表示されたとき | 色なしのコード |
| KaTeX | 数式が表示されたとき（0025 と同じ） | TeX の文字列 |
| mermaid | 図が表示されたとき（0025 と同じ） | 図の文字列をコードとして |

KaTeX と mermaid は 0025 の時点でこの形だった。
Shiki だけが、起動時と、本文を表示するたびに読み込みを始めていたので、コードブロックのないページでも約 1 MB（gzip 後で約 160 KB）を読み込んでいた。

### Shiki を読み込むかの判断

- コードブロック（`pre > code`）の部品が、`language-<言語名>` のクラスを見て読み込みを始める。
- 読み込むのは、色を付ける言語（`web/src/highlightLanguages.ts` の `HIGHLIGHT_LANGUAGES`）と、diff と言語を同時に指定したもの（`language-diff-<言語>`）だけにする。言語名のないブロック、知らない言語、mermaid では読み込まない。どうせ色が付かないからである。
- 言語の一覧は Shiki を読み込まずに判断するため、本体に持つ。Shiki に登録した言語の名前と別名から作り、Shiki の側と一致することをテストで確かめる。言語を足すときに片方だけを直すと、テストが落ちる。
- 本文の部品は読み込みを始めず、読み込み終わりを待って描き直すだけにする（`useLoaded`）。読み込みを始めるのはコードブロックの部品（`useLazy`）である。

### 読み込み器

`createLoader` に、読み込み終わりを知らせる `subscribe` を足す。
React の部品は `useSyncExternalStore` で読み込みの状態を読み、読み込み終わったら描き直す。
どこかの部品が読み込みを始めれば、同じライブラリを使うほかの部品もまとめて描き直される。

### 計測結果

Lighthouse のパフォーマンスは次のとおり変わった（手元の Apple Silicon、gzip を使う `serve` で配信）。

| ページ | コードブロック | 変更前 | 変更後 |
|---|---|---:|---:|
| `/` | なし | 79 | 83 |
| `/about` | なし | 78 | 83 |
| `/articles/syntax` | あり | 68 | 68 |
| `/articles/extensions` | あり | 55 | 57 |
| `/articles/getting-started` | あり | 71 | 67 |
| `/posts/ruby` | あり | 75 | 71 |

コードブロックのないページは、Shiki を読み込まなくなった分だけ上がった。
コードブロックのあるページは、本文を表示してから Shiki を読み込み始めるので、色が付くまでが遅くなり、いくつかのページで下がった。
1 回ずつの計測なので、数点の差にはばらつきも含まれる。

ブラウザでは、自己紹介とトップページでは Shiki、KaTeX、mermaid のどれも読み込まず、トップページからコードの記事に移ったときに初めて Shiki を読み込んで色が付くことを確かめた。

## 実装しないこと

- DB を読み込んだ時点で、表示するページの本文を調べて先に読み込みを始めること。コードのある記事で色が付くのは早くなるが、どのページでどのライブラリを使うかを本文から見積もる仕組みが要る。
- ページを移る前（リンクにマウスを乗せたときなど）の先読み。

## テスト設計

- 本体に持つ言語の一覧が、Shiki に登録した言語の名前と別名（と `jsx` の別名）に一致し、そのすべてを Shiki が読み込んでいること。
- 色を付ける言語と、diff と言語の組み合わせだけを読み込みの対象にし、mermaid、知らない言語、言語名のないもの、クラスのないものは対象にしないこと。
- 読み込み器が、読み込み終わったら登録した関数を呼び、登録を解いたものと、読み込みに失敗したときは呼ばないこと。
- 読み込む前は色なしで描き、読み込んだ後は色を付けること（既存のテスト）。

## トレードオフ

- コードのある記事では、色が付くまでが 0017 の形より遅くなる。記事を開いてから Shiki の読み込みが始まるからである。
- 色を付ける言語の一覧を、Shiki の登録とは別に持つ必要がある（テストで一致を確かめる）。
