# 0018 本文で許可する HTML

## 状態

採用。
0007 と 0016 の「本文中の生の HTML は表示しない（`skipHtml`）」を置き換える。

## 決定

本文中の HTML は、許可したタグと属性だけを残して表示する。
Markdown では書けない表現（折りたたみ、キー操作、ルビなど）を書けるようにするためである。

### 仕組み

react-markdown の `skipHtml` をやめ、次の順に処理する。

1. `remark-rehype` の `allowDangerousHtml` で、本文の HTML を構文木に残す。
2. `rehype-raw` で、その HTML を要素として取り込む。`<details>` の開始と終了の間に Markdown の段落を挟む書き方も、一つの要素にまとまる。
3. `rehype-sanitize` で、許可一覧（`web/src/sanitize.ts`）にないタグと属性を取り除く。
4. Shiki（ADR 0017）で色を付ける。sanitize より後に通すのは、先に通すと Shiki が付けた色の指定が取り除かれるためである。

### 許可するタグ

Markdown では書けない表現のために、次のタグを許可する。

| タグ | 用途 | 許可する属性 |
|---|---|---|
| `details`、`summary` | 折りたたみ | `details` の `open` |
| `kbd` | キー操作 | なし |
| `sub`、`sup` | 下付き、上付き | なし |
| `ruby`、`rt`、`rp` | ルビ | なし |
| `mark` | 蛍光ペンのような強調 | なし |
| `abbr` | 略語 | `title` |
| `dl`、`dt`、`dd` | 定義リスト | なし |
| `br` | 表のセルの中の改行 | なし |

sanitize は Markdown と GFM が作る要素も検査するので、それらのタグ（`p`、見出し、リスト、表、`pre`、`code`、`a`、`img`、タスクリストの `input`、脚注の `section` と `sup` など）も許可一覧に入れる。
その結果、これらのタグは本文に HTML で書いても残る。
属性は GitHub と同じ既定の許可一覧（`hast-util-sanitize` の `defaultSchema`）に従うので、たとえば `img` は `src` と `alt` などに限られる。

### 許可しないもの

- **`div`、`span`**：`class` や `style` を許さないので、付けても見た目が変わらない。
- **`b`、`i`、`s`、`strike`**：Markdown の `**`、`*`、`~~` と重複する。
- **`u`**：下線付きのリンクと見分けがつかない。
- **`iframe`、`script`、`style`、`object`、`embed`、`form`**：安全でないうえ、外部との通信が生じる。
- **`video`、`audio`**：自動再生の扱いなどを決めてから、別に検討する。

許可しないタグは、タグだけを外して中身の文字を残す。記事の文章が消えないようにするためである。
`script` と `style` は中身ごと取り除く（`rehype-sanitize` の既定）。
HTML のコメントも取り除く。`init` がトップページに置く説明のコメントも、これで表示されない。

### 属性

- `class`、`style`、イベント属性（`onclick` など）は取り除く。コードブロックの言語名（`language-*`）とタスクリスト、脚注のクラスは既定の許可一覧どおり残る。
- リンク先は `http`、`https`、`mailto` とサイト内のパスだけを残す。
- `id` は、脚注が作るもの（`user-content-` で始まるものと、脚注の見出しの `footnote-label`）だけを残す。本文の要素がページ内の要素と同じ ID を持つと、ページのほかの部分の動きを乱す恐れがあるためである。

### 脚注との兼ね合い

`remark-rehype` は、脚注の ID とリンク先にすでに `user-content-` を付けている。
`rehype-sanitize` の既定の設定は ID にもう一度この接頭辞を付けるので、ID が `user-content-user-content-fn-1` になり、リンク先の `#user-content-fn-1` と食い違って、脚注のリンクが飛ばなくなる。
そこで sanitize 側の接頭辞は付けず（`clobberPrefix: ""`）、代わりに上のとおり `id` の値を制限する。
脚注の見出しの ID（`footnote-label`）は `remark-rehype` が固定で付け、参照側の `aria-describedby` も同じ値を指すので、この値も許可する。

### 見た目

Tailwind の初期化用の CSS がブラウザ既定の見た目を消すので、`kbd`（枠）、`details` と `summary`（余白、カーソル）、`dl`（用語を太字、説明を字下げ）に最小限のスタイルを足す。

### 大きさ

`rehype-raw` は HTML パーサ（parse5）を持ち込むので、本体の JS が gzip 後で約 132 KB から約 186 KB になる。
Shiki のように後から読み込む形にはしない。
読み込むまでの間は `<details>` の中身が開いた状態で表示され、読み込み後に急に折りたたまれて見えなくなるからである。
色が後から付くのと違い、見えていた文章が消えるのは読み手を戸惑わせる。

## 実装しないこと

- `class` や `style` を使った見た目の指定。
- 動画、音声、外部の埋め込み（`iframe`）。
- HTML で書いた見出しへのページ内リンク（`id` を許さないため）。

## テスト設計

vitest で、本文の描画結果を検証する。

- `details` の中の Markdown が、空行で区切れば処理されること。`open` と、`summary` の中の `strong` と `code` が残ること。
- 許可した各タグ（`kbd`、`sub`、`sup`、ルビ、`mark`、`abbr` の `title`、定義リスト、表の中の `br`）が残ること。
- 許可しないタグは外れて中身の文字が残ること。`script`、`iframe`、`style`、`object` は中身ごと消えること。
- イベント属性、`style`、`class` が消えること。`javascript:` と `data:` のリンク先が消え、`https`、`mailto`、サイト内のリンクが残ること。
- 本文に書いた `id` が消え、脚注のリンクと `aria-describedby` がすべて行き先に届くこと。接頭辞が二重にならないこと。
- タスクリストのチェックボックスが残ること。`init` が作るコメントが表示されないこと。
- sanitize の後でも Shiki の色分けが残ること。`details` の中のコードブロックにも色が付くこと。

脚注の対策（sanitize 側の接頭辞をなくすこと、`id` を制限すること）は、どちらを外してもテストが失敗することを確認した。
ブラウザでは、`details` が閉じた状態で表示されてクリックで開くこと、中の Markdown とコードブロックの色、各タグの表示、`script` が実行されないことを確認した。

## トレードオフ

- 本体の JS が約 54 KB 増える。
- `<details>` の中で Markdown を使うには、CommonMark の規則どおり空行が要る。README に書き方の例を載せる。
- Markdown の出力に使うタグ（`img`、表など）は、本文に HTML で書いても許される。属性は既定の許可一覧で絞られる。
