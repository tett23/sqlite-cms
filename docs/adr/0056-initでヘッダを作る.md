# 0056 init でヘッダを作る

## 状態

提案。
0043 の「`init` は `content/header.md` を作らない」を改める。
0060 で、ヘッダの案内に「カテゴリ」（`/categories`）を足した。

## 決定

`init` で、`content/header.md` を作る。中身は、既定のヘッダと同じ見た目になるもの（サイト名、トップ、一覧、自己紹介、検索の案内、検索ボックス）で、見本（`example/content/header.md`）と同じにする。

0043 では、既定のヘッダで足りる人には要らないので作らなかった。
しかし、ヘッダを変えられることと、書き方（`{{title}}` の埋め込み、`{{> search}}` の検索ボックス、`{{! }}` のコメント）は、ファイルがないと気付きにくい。作ったファイルを直すだけで変えられるようにする。

- 作った直後の見た目は、作らないときと同じである。ファイルの先頭のコメントに、書かなければ既定のヘッダになることを書いておく。
- `--force` で作り直すときは、ほかの `init` が作るファイル（自己紹介のページなど）と同じく、上書きする。
- `init` の雛形（`cli/src/scaffold.rs` の `HEADER_MD`）と見本のヘッダが同じであることを、テストで確かめる。

## テスト設計

- `init` が `content/header.md` を作り、ビルドすると、サイト名を埋め込んだヘッダが DB に入ること（検索ボックスの場所の目印を含む）。
- `--force` で作り直すとき、ヘッダも上書きすること（上書きしたファイルの数）。
- 雛形のヘッダと見本のヘッダが同じであること。

## トレードオフ

- ヘッダのファイルがあると、SPA は DB を読むまでヘッダも本文も描かず、読み込み中の表示だけを出す（0043）。既定のヘッダは JS を読んだ時点で描けたので、新しく作ったサイトでは、ヘッダが出るのが DB を読み込むまで遅れる（本文は、もともと DB を読むまで出ない）。
- 既定のヘッダを変えても、`init` で作ったサイトのヘッダは変わらない（ファイルが優先される）。
