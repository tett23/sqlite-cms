# 0042 検索の候補

## 状態

提案。
0041 の「検索のページでは、ヘッダの検索ボックスを出さない」を改め、すべてのページで同じヘッダにする。
0041 で実装しないことにした「入力に合わせて候補を出すこと」を実装する。

## 決定

### 入力中の候補

ヘッダの検索ボックスに入力すると、その下に候補を 5 件まで出す（`web/src/suggest.ts` の `SUGGESTION_LIMIT`）。

- 候補は、検索のページと同じ検索（ADR 0031）の結果の先頭 5 件である。題名に言葉を含むものが先で、同じなら新しい順に並ぶ。
- 候補には、題名と、種類（ブログ、記事、ページ）と日付を出す。
- 一致するものがなければ、「『言葉』に一致する記事はありません。」と出す。
- 入力欄が空か空白だけのとき、入力欄から焦点が外れたとき、DB を読み込む前は出さない。

WAI-ARIA のコンボボックス（候補の一覧を持つ入力欄）として作り、キーボードと読み上げで使えるようにする。

| 操作 | 動き |
|---|---|
| 下の矢印 | 次の候補を選ぶ。最後の候補の次は入力欄に戻る |
| 上の矢印 | 前の候補を選ぶ。入力欄の前は最後の候補になる |
| Enter | 候補を選んでいればその記事に、選んでいなければ検索のページ（`/search?q=言葉`）に移る |
| Escape | 候補を閉じる |
| 候補を押す | その記事に移る |

- 入力欄に `role="combobox"`、`aria-expanded`、`aria-controls`、`aria-activedescendant` を付け、候補の一覧に `role="listbox"`、候補に `role="option"` を付ける。焦点は入力欄に置いたままにする。
- 候補の数（「候補が 5 件あります」「一致する記事はありません」）を、見えない `role="status"` で読み上げる。
- 候補を押したときに入力欄から焦点が外れて候補が閉じないよう、候補の上での `mousedown` の既定の動きを止める。
- 記事に移ったら、入力欄を空にして候補を閉じる。

### 検索のページのヘッダ

検索のページでも、ほかのページと同じくヘッダに検索ボックスを出す。

- 検索のランドマーク（`role="search"`）が二つになるので、ヘッダのものに「サイトの中を検索」、検索のページのものに「検索の条件」と名前を付けて区別する。
- 検索のページにいるままヘッダから検索したときも結果が変わるよう、ルーター（`web/src/router.tsx`）が、パスに加えて URL の問い合わせ（`?q=…`）も配る（`useSearch`）。
- 検索のページは、URL の `q` が変わったら（ヘッダからの検索、ブラウザの戻る）、入力欄をそれに合わせる。入力に合わせて URL を変えるときは、`navigate` の `replace` で、履歴を増やさずに置き換え、ルーターにも知らせる。これまでは `history.replaceState` を直接呼んでいたので、ルーターが URL の変化を知らなかった。
- 入力欄の末尾の空白は、URL に入れないが入力欄からは消さない（入力中に消えないようにするため）。

## 実装しないこと

- 候補の中で、言葉に一致した部分に印を付けること（検索のページで付ける）。
- 候補に「すべての結果を見る」を加えること。Enter か「検索」のボタンで検索のページに移れる。
- 入力を止めてから探すこと（入力を間引くこと）。記事の数が少なく、一回の検索は短い。

## テスト設計

- `suggest`：先頭の 5 件だけを、題名に言葉を含むものを先に返すこと。一致しなければ空、言葉が空か空白だけなら空を返すこと。
- `moveActive`：下の矢印で先頭から進み最後の次は入力欄に戻ること、上の矢印で逆に進むこと、候補がなければ選ばないこと。
- ルーター：渡した問い合わせを配ること。
- ヘッドレスの Chrome で、キーの入力（Chrome DevTools Protocol の `Input`）を使って次のことを確かめた。
  - 入力すると候補が 5 件出て、件数を読み上げる要素に書かれること。
  - 矢印のキーで選ぶ候補が動き、Escape で閉じ、Enter とクリックで記事に移ること。
  - 一致しないときにその旨が出ること。
  - 検索のページでヘッダから検索すると、URL、入力欄、結果が変わり、戻ると元に戻ること。
- 候補を開いた状態（候補あり、候補なし、検索のページ）で axe-core を実行し、違反がないことを確かめた。Lighthouse は入力しないので、候補を開いた状態を検査できない。

## トレードオフ

- 最初に入力したときに、検索の索引をブラウザで作る（ADR 0031）。記事が多いと、最初の一文字が遅れる。
- 候補は検索と同じ順なので、題名にも本文にも言葉を含む記事が多いと、題名だけでは選びにくいことがある。
