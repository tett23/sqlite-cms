# 0028 リンクカードの画像

## 状態

採用。
0025 の「リンクカードの題名、説明、画像」を実装しないことのうち、画像を改める（題名と説明は引き続き実装しない）。
0027 の「init は `.gitignore` に `.env` を書く」に、取得したもののキャッシュのディレクトリを加える。

## 決定

リンクカード（URL だけの行、ADR 0025）に、そのページの画像を表示する。

### 取得する時と場所

ブラウザからはほかのサイトの HTML を読めない（CORS）ので、CLI がサイトを組み立てるとき（`build`、`serve`、`deploy`）に取得する。

1. 本文（トップページ、post、article、page）から、URL だけの行の URL を集める。
2. そのページの HTML を取得し、`og:image`（なければ `og:image:url`、`og:image:secure_url`、`twitter:image`、`twitter:image:src`）の URL を読む。相対 URL はページの URL（転送された後のもの）を基準に解決する。
3. 画像を取得し、`/link-cards/<URL の BLAKE3 の先頭 16 文字>.<拡張子>` として配信するファイルに加える。
4. URL と画像のパスの対応を、DB の `link_cards` テーブル（マイグレーション 0006）に入れる。
5. SPA は DB から対応を読み、カードに画像を表示する。

画像は自分のサイトから配信するので、閲覧のときにほかのサイトと通信しない。
外部の画像を直接参照する方法（`<img src="https://…">`）は採らない。閲覧者の情報がほかのサイトに渡り、Cookie などでベストプラクティスの 100 点（ADR 0024）を保てなくなるおそれがあり、相手のサイトが画像を消すと表示が壊れるためである。
画像を DB に入れる方法も採らない。DB は最初の表示の前にすべて読み込むので、画像の分だけ最初の表示が遅れる。

### URL の集め方

CLI は Markdown を解釈しないので、SPA がカードにする段落と完全には一致しない。

- コードブロック（```` ``` ```` と `~~~`）の外の行のうち、行頭の引用（`>`）とリストの記号を外した残りが URL だけ（`https://…` か `<https://…>`）の行を集める。
- GFM の自動リンクが末尾に含めない文字（`.`、`,`、`?` など）で終わるものは集めない。SPA でもカードにならないためである。
- 段落の途中の URL だけの行も集める。SPA ではカードにならないので、画像が使われないだけで害はない。

### 画像の確かめ方

- 画像の形式は、応答の Content-Type ではなく、ファイルの先頭のバイトで確かめる。PNG、JPEG、GIF、WebP、AVIF のどれかでなければ使わない。エラーのページ（HTML）を画像として配信しないためである。SVG は使わない。
- 5 MB を超える画像は使わない。HTML は先頭の 1 MB までを読む（meta は head にある）。
- 取得は 1 件あたり 10 秒で打ち切る。User-Agent は `sqlite-cms/<版> (link card)` にする。
- 画像の URL が `http` と `https` 以外（`data:`、`javascript:` など）なら使わない。

### キャッシュ

取得した結果を、記事リポジトリの `.sqlite-cms-cache/link-cards/` に保存する。

- `<名前>.json` に URL と画像のファイル名（画像がなかったページは null）を、`<名前>.<拡張子>` に画像を保存する。
- 保存した結果があれば、取得し直さない。画像のなかったページも取得し直さない。
- 取得に失敗したもの（通信の失敗、画像でないもの、大きすぎるもの）は保存せず、次のビルドで取得し直す。
- 取り直すときは `.sqlite-cms-cache/` を消す。
- `init` は `.gitignore` に `.sqlite-cms-cache/` を書く（`.env` と同じく、なければ作り、行がなければ足す）。CI で公開するときは毎回取得し直すことになる。

取得できなかったものは警告を出して飛ばし、画像のないカードにする。
ほかのサイトの都合で、ビルドや公開が止まらないようにするためである。

環境変数 `SQLITE_CMS_OFFLINE` が空でも `0` でもなければ取得せず、保存した結果だけを使う。
ネットワークのない場所でのプレビューと、テストのためである。

### 表示

- カードの右に、幅 7.5rem、高さ 3.9rem（OGP の画像に多い 1.91:1）で、`object-fit: cover` で表示する。大きさを固定して、読み込んだときに本文がずれないようにする。
- 代替テキストは空にする。リンクの文字列（ホスト名と URL）を補う飾りだからである。
- `loading="lazy"` を付ける。
- sanitize は、`img` の `class` を `link-card-image` に、`loading` を `lazy` に限って残す。取り除いた後に空の `class` が残らないようにする。

## 実装しないこと

- ページの題名と説明（`og:title`、`og:description`）。
- 画像の縮小。画像を処理するライブラリが要る。OGP の画像は 1200×630 程度で、数百 KB のことが多い。
- キャッシュの期限。相手のページの画像が変わっても、`.sqlite-cms-cache/` を消すまで古い画像を使う。
- 取得の並列化。

## テスト設計

- URL の集め方：URL だけの行、`<URL>`、リストと引用の中、文中の URL、末尾の句読点、コードブロック（`` ` `` と `~`）の中、http(s) 以外。
- `og:image` の読み方：優先順位、属性の順序と引用符、大文字の `META`、文字参照、空の値、meta のないページ。
- 文字参照の戻し方（名前と数値、知らないもの）。
- 相対 URL の解決（絶対、スキームなし、絶対パス、相対パス、ほかのスキーム、空）。
- 画像の形式の見分け方（PNG、JPEG、GIF、WebP、AVIF、HTML、SVG）。
- 偽の取得先で、画像を取得して保存すること、二度目は保存した結果を使い、失敗したものだけを取り直すこと、オフラインでも保存した結果を使うこと。
- DB：`link_cards` に入ること、本文をすべて集めること。
- SPA：画像があればカードに `img` を付け、なければ付けないこと。本文に HTML で書いた `img` の `class` と `loading` は、カードのものだけを残すこと。DB から対応を読むこと。
- 結合テスト：テスト内に立てた偽のサイトから画像を取得して `link-cards/` と DB に入れ、取得できないものを警告すること。`.gitignore` に `.sqlite-cms-cache/` が書かれること。二度目はオフラインでも保存した結果を使い、取得しないこと。

ブラウザでは、見本の記事の zenn.dev のカードに画像が表示されることを確認した。

## トレードオフ

- ビルドがほかのサイトに依存する（取得できなければ画像が出ないだけで、止まりはしない）。初めてのビルドは取得の分だけ遅くなる。
- 相手のサイトの画像を自分のサイトから配信する。画像の権利は相手にあるので、載せてよいかは書き手が判断する。
- 画像を縮小しないので、カードの多いページは重くなる。
