# ADR 0063: ゆるいリストの段落の余白

ステータス: 採択

## 文脈

項目のあいだに空行のあるリスト（CommonMark の「ゆるいリスト」、loose list）では、項目の中身が `<p>` で包まれる。
本文の段落（`.article-body p`）には下に 1rem の余白を付けているので、ゆるいリストでは次の二か所に 1rem の隙間ができ、不自然に見える。

- 項目の文と、その下の入れ子のリストのあいだ（「作品の説明」と、その下の「解説」のあいだなど）。
- 入れ子のリストのない項目と、次の項目のあいだ。

入れ子のリスト自体（`li > ul`、`li > ol`）の下の余白は、すでに付けていない。今回の隙間は、リストの中の段落の余白による。

## 実装すること

- リストの項目の中の段落（`.article-body li > p`）には、下の余白を付けない。項目の文と入れ子のリストのあいだ、項目と項目のあいだが、空行のないリスト（きついリスト、tight list）と同じ詰まり方になる。
- 一つの項目に段落が二つ以上あるとき（`li > p + p`）だけ、段落のあいだに 0.5rem を空ける。段落の区切りが分からなくならないようにするためである。
- 見本の「記法の一覧」に、項目のあいだに空行のある入れ子のリストを足し、E2E で確かめる。

## 実装しないこと

- ゆるいリストの項目と項目のあいだを、きついリストより空けること。GitHub などは空けるが、このサイトでは、空行の有無で見た目が変わらないほうがよいと判断した。
- Markdown の解析を変えて、ゆるいリストを `<p>` で包まないこと。CommonMark の決まりから外れる。

## テスト設計

- E2E：見本の「記法の一覧」のゆるいリストで、項目の文（`li > p`）の下端と、入れ子のリストの最初の項目の上端のあいだが 0 であること。入れ子のリストの最後の項目の下端と、次の項目の上端のあいだが 0 であること。一つの項目の二つの段落のあいだが 0.5rem（8px）であること。
- 直す前の CSS で、この E2E が失敗することを確かめる。

## トレードオフ

- ゆるいリストで、項目と項目のあいだを空けて読みやすくする書き方ができなくなる（空行の有無で見た目が変わらない）。
- 項目の中に段落が複数あるときだけ、段落のあいだが本文の段落（1rem）より狭い 0.5rem になる。
