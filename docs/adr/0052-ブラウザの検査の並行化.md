# 0052 ブラウザの検査の並行化

## 状態

提案。
0044 の「CI は一つのジョブのままにし、E2E と Lighthouse を順に行う」を、ビルドとテストの後の別々のジョブで並行して行う形に改める。
0050 の「Core Web Vitals は、ページを一つずつ計測する」は、一つの機械の中では変えない。
v0.1.6 のリリースで、分けた計測の最初のページ（`/`）だけが LCP 2.58 秒、INP 160 ms で失敗した（起動した直後の Chrome と機械が遅い）。分けると最初のページが二つになり、起きやすくなる。計測の前に、計測するページを絞らずに一度ずつ開くことにした（キャッシュを使わずに計測するので、計測するページの読み込みは速くならない）。v0.1.6 のタグには Release がない。

## 背景

Core Web Vitals の計測（0050）を足して、CI の一つのジョブが約 4 分になった。そのうち 3 分がブラウザの検査だった（v0.1.4 の CI）。

| 段階 | 時間 |
|---|---:|
| セットアップ、npm ci、SPA のビルド、vitest、clippy、cargo test | 約 50 秒 |
| E2E | 49 秒 |
| Lighthouse（3 つ並行） | 46 秒 |
| Core Web Vitals（14 ページを順に） | 84 秒 |

リリースでも、Linux のビルドのジョブ（253 秒）が、ブラウザの検査の分だけ macOS のジョブ（153 秒）より長く、Release を作るまでの時間を決めていた。

0044 では、ジョブを分けるとセットアップが重なって遅くなる見込みだったので、一つのジョブにした。
当時はブラウザの検査が 1 分半ほどで、セットアップ（20 秒ほど）を重ねる意味が薄かった。今は 3 分あり、並行にすれば重なるセットアップより縮む分が大きい。

## 決定

- CI の `test` のジョブは、SPA のビルド、vitest、clippy、`cargo test` までを行い、`cargo test` が作った `target/debug/sqlite-cms` を Artifact（保存は 1 日）にする。
- `browser` のジョブ（`test` の後）を、E2E、Lighthouse、Core Web Vitals の 1/2、2/2 の 4 つに分け、別々の機械で並行して行う。Rust のツールチェーンは要らず、checkout、Node のセットアップ、npm ci、バイナリの受け取りだけを行う。
- Core Web Vitals は、ページを交互に二つに分ける（`WEB_VITALS_SHARD` に `1/2`、`2/2`。`web/scripts/pages.mjs` の `shard`）。重いページが片方に偏らないよう、交互に分ける。別々の機械なので、CPU を取り合って INP や LCP が揺れることはない（一つの機械で並行にしないのは 0050 と同じ理由）。
- どれかの検査が失敗しても、ほかの検査を最後まで行い、レポートを残す（`fail-fast: false`）。
- リリースも同じ形にする。Linux のビルドが梱包したバイナリを受け取り、4 つの検査を並行して行う。Release を作るジョブは、ビルドとブラウザの検査の両方を待ち、梱包したバイナリだけを添付する。

見込みでは、CI は約 4 分から、50 秒（`test`）＋ Artifact の受け渡し ＋ 30 秒ほど（セットアップ）＋ 最も長い検査の 50 秒ほどで、2 分半ほどになる。

## 実装しないこと

- E2E と Lighthouse をさらに分けること。どちらも 50 秒ほどで、Core Web Vitals を二つに分けたものと同じくらいなので、分けても全体は縮まない。
- ブラウザの検査のジョブで、`node_modules` そのものをキャッシュすること。npm ci は npm のキャッシュを使って 10 秒ほどで、キャッシュの復元とほとんど変わらない。
- Core Web Vitals の計測の待ち時間（ページを開いた後の 2 秒）を縮めること。後から読み込むもの（数式、図）が描き終わる前に操作すると、計測の条件が変わる。

## テスト設計

- `shard`（vitest）：二つに分けたものが重ならず、合わせるとすべてのページになること。交互に分けること。指定がなければすべてを返し、書き誤り（0/2、3/2、1/0、1、a/b）はエラーにすること。
- ワークフローは actionlint で検査した。

## トレードオフ

- 使う機械の数（と合計の時間）は増える。CI の待ち時間を縮めるためである。
- バイナリ（約 34 MB）を Artifact で受け渡すので、その分の時間がかかる。
- 一つの検査だけを見たいとき、実行結果の画面でジョブが分かれる。
