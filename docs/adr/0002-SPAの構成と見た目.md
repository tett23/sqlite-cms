# 0002 SPA の構成と見た目

## 状態

採用。

## 決定

Vite + React + TypeScript の SPA とする。
CSS は Tailwind（v4、`@tailwindcss/vite`）で書く。

### DB の取得と保持

- 起動時に `/db/manifest.json` を `cache: "no-cache"` で取得し、現行 DB の URL を解決する。
- DB ファイルを fetch し、sql.js（wasm）で開く。DB は React の外のモジュールスコープに一度だけ保持する。
- 取得完了までは「読み込み中」の一行だけを表示する。失敗時はエラーの一行を表示する。

### ルーティング

react-router の BrowserRouter を使う。

- `/`：記事一覧。日付降順で title と date を並べる。
- `/articles/:slug`：記事本文。DB の `body_html` を表示する。
- 不明な slug と不明なパスは「見つかりません」の一行を表示する。

### 見た目

- 白背景、黒文字。装飾、影、アニメーション、スクロール効果は持たない。
- 本文カラムは最大幅 65ch 相当、左右パディングのみ。中央寄せ。
- リンクは下線付きの青（訪問済みは紫でよい）。
- 記事本文の HTML はグローバル CSS で最小限のスタイル（見出し、段落間隔、コードブロック）を与える。Tailwind の typography プラグインは使わない。

## 実装しないこと

- 検索 UI、タグ絞り込み、ページネーション。記事数が一覧表示に耐えなくなった時点で ADR を追加する。
- Service Worker とオフライン対応。ブラウザの HTTP キャッシュに任せる。
- ダークモード。

## テスト設計

- `tsc --noEmit` を CI の必須チェックとする。
- DB 取得とクエリのラッパー（`src/db.ts`）を vitest でテストする。フィクスチャ DB を fetch のモック経由で与え、一覧クエリと slug 引きの結果を検証する。
- コンポーネントのレンダリングテストは書かない。表示ロジックが自明なためである。

## トレードオフ

- BrowserRouter は配信側に SPA フォールバック（全パス → index.html）を要求する。Cloudflare の静的アセット配信はこれを設定一つで持つため、ハッシュルーティングの見た目の悪さを避ける側を取る。
- sql.js の wasm（約 600KB、圧縮後は小さい）が初回ロードに乗る。記事遷移をローカル参照にする対価として受け入れる。
