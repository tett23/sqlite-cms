# 0013 JS 依存の更新と削減

## 状態

採用。
0002 の「ルーティングに react-router を使う」を置き換える。

## 決定

`web/` の JS ライブラリをすべて最新にし、自前で簡単に書けるものは実装して依存から外す。

### 自前の実装に置き換えたもの

- **react-router**：使っていたのは、パターンとパスの照合、リンク、現在のパスの取得だけだった。`web/src/router.tsx` に置き換える。
  - `Router`：`history` の `popstate` と、自前の遷移イベントで現在のパスを配る。テストのために、パスを直接渡しても使える。
  - `Link`：修飾キーなしの左クリックだけを `pushState` による遷移にする。Ctrl や ⌘ を押したクリック、中ボタン、`target` 付きのリンクはブラウザに任せる（新しいタブで開けるようにするため）。
  - `matchPath`：`/posts/:slug` のようなパターンと照合し、パラメータを URL デコードして返す。末尾のスラッシュは無視する。
  - ページのコンポーネントは、`useParams` ではなく引数で `slug` を受け取る。
- **@types/sql.js**：使っている API だけを `web/src/types/sql.js.d.ts` で宣言する。@types/sql.js が引き込んでいた @types/emscripten と @types/node も消える。
- **テストでの Node の API**：マイグレーションの SQL を `node:fs` で読んでいた箇所を、Vite の `import.meta.glob`（`?raw`）に置き換える。これで `tsconfig.json` の `types` から `node` を外せる。

### 残したもの

| ライブラリ | 残す理由 |
|---|---|
| react、react-dom | UI の土台 |
| react-markdown、remark-gfm | CommonMark と GFM に従うパーサを書き直すのは簡単ではない |
| sql.js | SQLite の wasm そのもの |
| tailwindcss、@tailwindcss/vite | 当初の要件で Tailwind の使用が指定されている |
| vite、vitest、typescript | ビルド、テスト、型検査の道具 |
| @vitejs/plugin-react | 開発時の Fast Refresh は簡単には再現できない |
| @types/react、@types/react-dom | React の型 |

### 更新

- vite 7 → 8（バンドラが Rolldown になる）、@vitejs/plugin-react 4 → 6、vitest 3 → 5、ほかは同じメジャーの最新にする。
- vitest 3 系にあった脆弱性（@vitest/mocker のパストラバーサル）は、vitest 5 で解消する。`npm audit` の報告は 0 件になる。
- 設定ファイル（`vite.config.ts`、`tsconfig.json` の `types` を除く）は変更なしで動く。

### 効果

手元（Apple Silicon）での測定では次のとおり。

- `npm run build`（型検査とバンドル）が約 1.3 秒から約 0.5 秒になった。主に vite 8 による。
- JS バンドルが gzip 後で約 148 KB から約 131 KB になった。react-router を外した分である。
- インストールされるパッケージが 62 個減った。

## 実装しないこと

- ルーターの入れ子のルート、データの読み込み、遷移のブロックなどの機能。今のページ構成では要らない。
- スクロール位置の復元。遷移のたびに先頭に戻す（従来どおり）。

## テスト設計

- `matchPath`：固定パスの完全一致、末尾のスラッシュ、パラメータの取り出しとデコード、空のパラメータ、壊れたエスケープ。
- `shouldNavigateInApp`：修飾キーなしの左クリックだけを SPA 内の遷移にすること、修飾キー、中ボタン、`target="_blank"`、ほかの処理が止めたクリックをブラウザに任せること。
- `Router` と `Link`：渡したパスを配ること、`Link` が `href` と属性を持つ `a` 要素になること。
- ブラウザでの確認：リンクのクリック、本文中のリンク、戻る、進むで、ページが再読み込みされないこと。存在しないパスで「見つかりません」になること。開発サーバで Fast Refresh が有効なこと。

## トレードオフ

- ルーターを自前で持つので、ブラウザの履歴の扱いの不具合は自分で直すことになる。範囲は `pushState` と `popstate` だけで、テストでほぼ押さえられる。
- sql.js の型を自前で持つので、sql.js の API が変わったときに型が追随しない。使う API を増やすときは宣言も足す必要がある。
