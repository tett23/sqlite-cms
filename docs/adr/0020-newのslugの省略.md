# 0020 new の slug の省略

## 状態

採用。
0015 の「`new <種別> <SLUG> [SITE_DIR]`（SLUG は必須）」を改める。

## 決定

`new` の SLUG を省略できるようにする。

```
sqlite-cms new <post|article|page> [SLUG] [SITE_DIR] [--title <TITLE>] [--date <YYYY-MM-DD>]
```

### 省略したときの slug

- 記事の日付（`YYYY-MM-DD`）を slug にする。日付は記事に書き込む日付と同じもの（`--date`、なければ `site.toml` の `timezone` で決まる今日）を使い、ファイル名と記事の日付が必ず一致するようにする。
- 同じ種別のディレクトリに同じ名前のファイルがあれば、`-2`、`-3` と枝番を付ける（`2026-09-26-2`）。一本目には枝番を付けない。
- 枝番は種別ごとに数える。post と article に同じ日付の記事があっても、互いに枝番を付けない（URL が `/posts/...` と `/articles/...` で分かれるため）。
- ファイルは「すでにあれば作らない」方法（`create_new`）で作り、作れなければ次の枝番を試す。存在を確かめてから作る方法と違い、その間に別の処理が同じ名前で作っても上書きしない。書き手が手で作った同じ名前のファイルも、飛ばして次の枝番にする。
- 枝番は 1000 までとし、使い切ったら slug の指定を求める。
- タイトルを省くと、これまでどおり slug（ここでは日付）をタイトルにする。
- page は日付を持たないので、slug を省けない。

slug を明示して、そのファイルがすでにある場合は、これまでどおりエラーにし、枝番は付けない。
書き手が決めた名前を黙って変えないためである。

### 引数の見分け方

slug を省けるようにすると、`new post ../blog` の `../blog` が slug なのか SITE_DIR なのかが決まらなくなる。
slug に使える文字は文字、数字、`-`、`_` だけ（0015）なので、次の規則で見分ける。

- 種別の後の引数が一つで、`/`（や `\`）を含むか `.` で始まるときは、SITE_DIR とみなす。slug としては必ず不正な形だからである。
- それ以外の一つの引数は、これまでどおり SLUG とみなす。`blog` のような区切りのない名前でディレクトリを指したいときは、`./blog` と書く。
- 引数が二つなら、SLUG と SITE_DIR の順に読む。

## 実装しないこと

- 日付以外の規則（連番、タイトルからの生成など）での slug の生成。
- SITE_DIR を指すための専用のオプション（`-C` など）。上の見分け方で足りる。

## テスト設計

- 引数の解釈：slug なし、slug のみ、区切りのない名前（slug とみなす）、`../blog`、`./blog`、`blog/`、`.`（SITE_DIR とみなす）、slug と SITE_DIR の両方、page での省略のエラー。
- 作成：日付、`-2`、`-3` の順に作られること。タイトルを省くと日付がタイトルになること。手で作った同じ名前のファイルを上書きせず次の枝番にすること。枝番を種別ごとに数えること。page で省くとエラーになること。
- 結合テスト：slug を省いて二回作ると日付と `-2` のファイルができ、そのままビルドできること。`--date` がなくても、ファイル名と記事の日付が一致すること（`site.toml` の `timezone` と、異なる環境変数 `TZ` を与えて確かめる）。`./site` のようなパスで記事リポジトリを指せること。

## トレードオフ

- 区切りのない名前は slug とみなすので、`new post blog` で `blog` というディレクトリを指すことはできない（`./blog` と書く必要がある）。README とヘルプに書く。
- 日付の slug は URL として内容を表さない。日々のメモのように名前を考えたくない記事に向く。
