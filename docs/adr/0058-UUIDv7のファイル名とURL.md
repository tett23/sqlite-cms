# 0058 UUIDv7 のファイル名と URL

## 状態

提案。
0001 の「slug はファイル名から取る」と、`sqlite-cms new` の「slug を省くと日付にし、同じ日付には枝番を付ける」を改める。
0059 で、article は frontmatter の slug を URL にできるようにし、同じ日付の並びを、slug ではなくファイル名から取った鍵で決めるようにした。

## 背景

一覧は日付の新しい順に並べ、同じ日付の中は slug の降順にしていた。
slug は書き手が付けた名前か日付（と枝番）で、同じ日付の記事の順は、作った順と関係がなかった。

## 決定

post と article のファイル名の先頭に UUIDv7（RFC 9562）を付け、URL の slug を常にその UUIDv7 にする。
UUIDv7 の先頭の 48 ビットは作った時刻（ミリ秒）なので、slug の順が作った順になり、同じ日付の記事も一意に並ぶ。

### `sqlite-cms new`

| 種別 | ファイル名 | タイトル |
|---|---|---|
| post | `<UUIDv7>.md`。slug を指定すれば `<UUIDv7>-<slug>.md` | 省くと日付 |
| article | `<UUIDv7>-<タイトル>.md`。slug を指定すれば `<UUIDv7>-<slug>.md` | 必須（`--title`） |
| page | `<slug>.md`（今までどおり。slug は必須） | 省くと slug |

- UUIDv7 は自前で作る（`cli/src/uuid.rs`）。乱数は、標準ライブラリの `RandomState`（プロセスごとに乱数で初期化される SipHash の鍵）で時刻をかき混ぜて作る。暗号に使う乱数ではないが、同じミリ秒に作ったものを区別するには足りる。依存を足さない。
- タイトルをファイル名に入れるときは、文字、数字、`_` 以外を `-` にし、続く `-` は一つにまとめ、50 文字までにする（`SQLite と CMS / 2026` → `SQLite-と-CMS-2026`）。日本語の文字はそのまま残る。使える文字がなければ `<UUIDv7>.md` にする。
- 枝番（`-2`、`-3`）は付けなくなった。UUIDv7 が重なることはまずないので、同じ名前のファイルがあればエラーにする。

### ファイル名から slug を取る

- ファイル名（拡張子を除く）が UUIDv7 だけか、UUIDv7 の後に `-` で続くものなら、UUIDv7 を slug にする（`cli/src/db.rs` の `slug_of`）。UUIDv7 の英字は小文字だけを認める。
- そうでないファイル（UUIDv7 を使う前に書いた記事）は、今までどおりファイル名を slug にする。公開済みの URL は変わらない。
- 固定ページ（`pages/`）は、今までどおりファイル名が slug（`/about`）。
- 同じ slug になるファイルが二つあれば（UUIDv7 が同じで後ろの名前が違うなど）、ファイル名を挙げてビルドをエラーにする。

### 見本

見本（`example/`）の post と article を `<UUIDv7>-<今までの名前>.md` に改めた。
UUIDv7 の時刻は記事の日付（日本時間の 9 時）にし、同じ日付の中は、今までの並び（今までの slug の降順）が保たれるよう、今までの slug の順に 1 秒ずつずらした。乱数の部分は、今までの名前のハッシュから決めた（作り直しても同じになる）。
post の URL は UUIDv7 に変わったので、本文の中のリンク、E2E と計測のページの一覧（`web/scripts/pages.mjs`）を、新しい URL に改めた。
article は、今までの名前を frontmatter の slug に書いて（0059）、今までの URL のままにした。

## 実装しないこと

- 今までの名前のファイルを、UUIDv7 の名前に改めるコマンド。URL が変わるので、書き手が改めるかを決める。
- 古い URL から新しい URL への転送。
- page に UUIDv7 を付けること。

## テスト設計

- UUIDv7：RFC 9562 の例と同じ並びになること。作ったものが UUIDv7 として読め、毎回違い、時刻の順に並ぶこと。UUIDv7 で始まるファイル名だけを認めること（大文字、ほかの版、variant の違い、区切りの違い、後ろに `-` 以外が続くものを認めない）。
- `new`：post の名前が UUIDv7 だけで、タイトルが日付になること（タイムゾーンの日付と一致すること）。article の名前が UUIDv7 とタイトル（置き換えた形）になり、タイトルを省けないこと。slug を指定すれば UUIDv7 の後ろに付くこと。page は今までどおりで、同じ名前を上書きしないこと。タイトルの置き換え（記号、続く `-`、長さの上限、使える文字がないとき）。
- DB：UUIDv7 で始まるファイルは UUIDv7 を、そうでないファイルと固定ページはファイル名を slug にすること。同じ slug になるファイルがあればエラーにすること。同じ日付の二つの post を `new` で作って組み立てると、slug が UUIDv7 になること。
- E2E、Lighthouse、Core Web Vitals：新しい URL の見本で、すべて通ること。

## トレードオフ

- URL が長く、読んでも中身が分からない。ファイル名の後ろの名前は、URL に入らない。
- 見本の post の URL が変わった。見本を公開しているサイト（Cloudflare の Worker）では、今までの post の URL が見つからなくなる（article は変わらない）。
- 一覧の順は、日付が同じなら作った順になる。日付を書き換えても、UUIDv7 は作った時刻のまま変わらない。
