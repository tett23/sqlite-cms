# 0026 serve の gzip 圧縮

## 状態

採用。
0023 の「`serve` での応答の圧縮」を実装しないことを改める。

## 決定

`sqlite-cms serve` は、要求の `Accept-Encoding` が gzip を受け付けるなら、応答を gzip で圧縮して返す。
本番の Cloudflare は応答を圧縮して配信するので、手元のプレビューと Lighthouse の計測（ADR 0019）を本番に近づけるためである。
0023 のとおり、圧縮しないと Lighthouse は JS と wasm を圧縮前の大きさで、遅い回線を模して見積もり、パフォーマンスを大きく低く出していた。

### 圧縮するもの

- 種類：テキスト（`text/*`）、JSON、XML、wasm、DB（`application/vnd.sqlite3`）、SVG、ttf、otf。
- SVG 以外の画像、woff と woff2、音声、動画、zip などは、すでに圧縮されているので圧縮しない。
- 256 バイト未満の応答は圧縮しない。gzip の枠（18 バイト）の分だけ、かえって大きくなることがある。
- 状態が 200 の応答だけを圧縮する。
- 圧縮できる種類の応答には、圧縮したかどうかにかかわらず `Vary: Accept-Encoding` を付ける。
- `Accept-Encoding` は大文字と小文字を区別せずに読む。`gzip;q=0` は拒否とみなす。gzip の指定がなければ `*` に従う。
- HEAD には、GET と同じ（圧縮した）`Content-Length` を返す。

配信する中身は起動の後に変わらないので、圧縮した結果を中身（BLAKE3 のハッシュ）ごとに覚えておき、同じものは一度だけ圧縮する。
起動の時にすべてを圧縮しないのは、`cargo run`（最適化なしのビルド）で起動の表示が遅れないようにするためである。

### 圧縮の実装

依存を足さず、gzip（RFC 1952）と DEFLATE（RFC 1951）の圧縮を自前で書く（`cli/src/gzip.rs`、約 200 行）。

- DEFLATE のブロックは、固定ハフマン符号のもの一つだけにする。動的ハフマン符号の表を作らないぶん、実装が小さい。
- 繰り返しは LZ77 で置き換える。同じ 3 バイトで始まる位置をハッシュで連鎖させ、64 個まで候補をたどって最長の一致を探す。一つ先の位置でもっと長い一致があれば、今の位置をリテラルにする（遅延評価）。
- 展開は実装しない。`serve` は展開する必要がない。

圧縮率は、zlib の既定（レベル 6）より 1〜2 割劣る。

| ファイル | 圧縮前 | 自前の gzip | zlib（レベル 6） |
|---|---:|---:|---:|
| 本体の JS | 612 KB | 214 KB | 188 KB |
| Shiki の JS | 1,070 KB | 182 KB | 161 KB |
| sql.js の wasm | 658 KB | 375 KB | 323 KB |

本番の Cloudflare は Brotli か gzip で圧縮するので、手元の計測は本番よりやや悪く出る。
手元のプレビューと、計測の傾向を見るには十分である。

### 計測結果

Lighthouse のパフォーマンスは次のとおり変わった（手元の Apple Silicon）。

| ページ | 圧縮なし | gzip |
|---|---:|---:|
| `/` | 65 | 80 |
| `/articles/syntax` | 54 | 68 |
| `/articles/extensions` | 42 | 54 |
| `/articles/getting-started` | 57 | 71 |
| `/posts/ruby` | 58 | 75 |
| `/about` | 65 | 78 |

トップページの Largest Contentful Paint は 13.4 秒から 5.4 秒になった。

## 実装しないこと

- Brotli。gzip より圧縮率は高いが、実装がずっと大きい。
- 動的ハフマン符号。圧縮率は zlib に近づくが、手元のプレビューには要らない。
- `build` の出力に圧縮済みのファイルを置くこと。Cloudflare が配信の時に圧縮する。

## テスト設計

- CRC-32 が既知の値と一致すること。
- 空、1 バイト、短い繰り返し、日本語を含む JS、長い同じ文字の並び、周期のある並び、乱数、全バイト値、窓（32 KiB）を超える距離の繰り返しを圧縮し、システムの `gzip -dc` で元に戻ること（macOS と CI の Ubuntu には gzip がある）。
- 繰り返しの多いテキストが 20 分の 1 未満になること。
- `serve`：gzip を受け付けるときだけ圧縮し、`Vary` を付けること。小さい応答、圧縮済みの種類、200 以外の応答を圧縮しないこと。`Accept-Encoding` の読み方（大文字と小文字、`q=0`、`*`）。同じ中身は一度だけ圧縮すること。
- 結合テスト：起動した `serve` に `Accept-Encoding: gzip` で要求すると、`Content-Encoding: gzip`、`Vary`、圧縮後の `Content-Length` が付き、展開すると圧縮しない応答と一致すること。

## トレードオフ

- 初めて要求されたファイルは、圧縮の分だけ応答が遅れる（最適化なしのビルドで、1 MB あたり 1 秒未満）。
- 圧縮の実装を自分で保守する必要がある。
