# ADR 0066: ブラウザの検査は、見本のキャッシュをコミットして外部と通信せずに行う

ステータス: 採択

## 文脈

E2E、Lighthouse、Core Web Vitals（ブラウザの検査、[ADR 0052](0052-ブラウザの検査の並行化.md)）は、`sqlite-cms serve` で `example/` を配信して行う（`web/scripts/server.mjs`）。
CI には `example/.sqlite-cms-cache/` がない（`example/.gitignore` で Git から外している）ので、検査のたびに、見本の記事のリンクカードの画像（[ADR 0028](0028-リンクカードの画像.md)）とコードの埋め込み（[ADR 0065](0065-embed-github-files-and-gists.md)）を、外部のサイトから取得し直す。

v0.5.0 の main の CI で、E2E が一度落ちた。
GitHub がリポジトリの OGP の画像（`opengraph.githubassets.com`）に 429（回数の制限）を返し、リンクカードの画像を取得できず、画像を確かめる場面が失敗した。
E2E は同じ見本の写しを三つ配信する（既定のヘッダ用と、`base_path` 用）ので、同じ URL を三度、同時に取得する。CI の並行するジョブ（E2E、Lighthouse、Core Web Vitals 2 つ）と、リリースのワークフローも、それぞれ取得する。

外部のサイトの都合（回数の制限、障害、中身や画像の差し替え）で検査が落ちるのは、変更の良し悪しと関係がない。
また、外部の中身が変わると、計測の結果（Lighthouse の点数、画像の大きさ）も変わり、版ごとに比べられなくなる。

## 実装すること

### 見本のキャッシュをコミットする

- `example/.gitignore` から `.sqlite-cms-cache/` の行を消し、`example/.sqlite-cms-cache/` をコミットする。中身は、見本のすべてのリンクカードの画像（元の画像と、カードの大きさの WebP）と、コードの埋め込みの結果である。
- コミットする前に `example/.sqlite-cms-cache/` を消してから、見本を通信して組み立て直し（`sqlite-cms build example`）、見本のすべての URL の結果がそろっていることを確かめる。警告（取得できなかったもの）が出たら、出なくなるまで取り直す。
- `init` が作る `.gitignore`（記事リポジトリ向け）は変えない。キャッシュをコミットするのは、見本だけである。

### ブラウザの検査は通信しない

- `web/scripts/server.mjs` は、`sqlite-cms serve` を `SQLITE_CMS_OFFLINE=1` で起動する。保存した結果だけを使い、外部と通信しない（[ADR 0028](0028-リンクカードの画像.md)）。
- 手元でも CI でも同じにする。E2E が写す見本にも、キャッシュがそのまま写る。

### 見本の URL を変えたとき

- 見本に URL だけの行を足したり変えたりしたら、`sqlite-cms build example`（通信する）で取得して、増えたキャッシュをコミットする。DEVELOPMENT.md に手順を書く。
- 取り忘れたとき、検査ではその URL のカードに画像がない（コードの埋め込みならリンクカードになる）だけで、検査そのものは、画像や埋め込みを確かめる場面のほかは通ってしまう。そこで、見本の URL のキャッシュがそろっていることを確かめるテストを足す（テスト設計）。

## 実装しないこと

- 記事リポジトリ（`init` で作るもの）で、キャッシュをコミットすることを勧めること。
- 取得の失敗を、取り直す（リトライする）こと。検査が通信しなくなれば、要らない。
- 結合テスト（`cli/tests`）の変更。すでに `SQLITE_CMS_OFFLINE=1` で動き、取得のテストは偽のサイトから取得する。
- 取得そのもの（リンクカードとコードの埋め込み）の、通信するテストを CI で行うこと。

## テスト設計

- CLI の単体テスト：見本（`example/`）の本文の、URL だけの行のすべてについて、`example/.sqlite-cms-cache/` に結果があること（リンクカードは JSON、コードの埋め込みは対象の URL の JSON）。ないときは、その URL と、取り直す手順を出して失敗する。
- E2E：今の場面（リンクカードの画像が 240 × 126 の WebP であること、コードの埋め込みが出ること）が、通信せずに通ること。
- CI のログに「取得しています」が出ないこと（通信していないこと）を、一度目で見て確かめる。

## トレードオフ

- 見本のキャッシュ（今は 180 KB ほど。元の画像を含む）が、リポジトリに入る。画像の多くは他人のサイトの OGP の画像である。見本は配布物（リリースのアーカイブ）に含めない。
- 見本の URL の先の中身が変わっても、キャッシュを取り直すまで気づかない。検査が外部に左右されないことを、そちらより優先する。
- 見本の URL を足したら、キャッシュも取ってコミットする手間が増える。忘れたら、単体テストが知らせる。
