# 0041 ヘッダの検索ボックス

## 状態

提案。
0031 の「ヘッダに『検索』を置く」に、検索ボックスを加える。

## 決定

ヘッダの案内の横に、検索ボックス（入力欄と「検索」のボタン）を置く。
言葉を入れて送ると、検索のページ（`/search?q=言葉`）に移る。

- 検索のページ（`/search`）はそのまま残す。`/search?q=言葉` の URL で検索した結果を開けること（パーマリンク）を保つためである。ヘッダの案内の「検索」も残す。
- 検索のページでは、ヘッダの検索ボックスを出さない。ページに自分の検索欄があり、同じページに二つあると紛らわしい。検索のランドマーク（`role="search"`）が二つあると、読み上げで区別する名前も要る。
- 検索ボックスは `<form action="/search" method="get">` の `q` にする。JS が動くときはページを読み直さずに移り、動かなくてもフォームとして同じ URL を開ける。`action` はサイトを置くパス（ADR 0030）から始める。
- URL（`/search` と `?q=`）は、ヘッダの検索ボックスと検索のページで同じ関数（`web/src/search.ts` の `searchPath`）で作る。言葉は前後の空白を除いて入れ、空なら `?q=` を付けない。
- 入力欄の名前は、見えない `label`（「サイトの中を検索」）で付ける。
- 検索ボックスは DB を読む前から描く。後から現れてヘッダの高さが変わらないようにするためである。
- 狭い画面では、案内の下の行に置く。

## 実装しないこと

- 入力に合わせて候補を出すこと（検索のページで入力に合わせて結果を出すので足りる）。
- 検索のページで、ヘッダの検索ボックスに言葉を残すこと。

## テスト設計

- `searchPath`：言葉の前後の空白を除いて `?q=` に入れ、記号を URL の形にすること。空と空白だけのときは `?q=` を付けないこと。
- ヘッドレスの Chrome で次のことを確かめた。
  - 送ると `/search?q=言葉` に移り、検索のページの入力欄に言葉が入り、結果が出ること。
  - 検索のページではヘッダの検索ボックスを出さず、戻るとまた出ること。
  - `/search?q=言葉` を直接開くと、結果が出ること。
- Lighthouse で、すべてのページのユーザー補助とおすすめの方法が 100 点であること（CI）。

## トレードオフ

- ヘッダの幅を使う。広い画面ではサイト名と同じ行に、狭い画面では一行増える。
- 検索のページとほかのページで、ヘッダの見た目が変わる。
