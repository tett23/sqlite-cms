# 0025 Markdown の拡張

## 状態

採用。
0018 の「`div`、`span` は許可しない」を、拡張が使うクラスを持つものに限って改める。

## 決定

[Zenn の Markdown 記法](https://zenn.dev/zenn/articles/markdown-guide)を参考に、CommonMark と GFM に次の拡張を加える。
`@[gist](URL)` のような `@` で始まる埋め込みの記法は実装しない。

| 記法 | 書き方 | 出力 |
|---|---|---|
| メッセージ | `:::message` 〜 `:::` | `<div class="message" role="note">` |
| 警告のメッセージ | `:::message alert` 〜 `:::` | `<div class="message message-alert" role="note">` |
| 折りたたみ | `:::details 見出し` 〜 `:::` | `<details><summary>見出し</summary>…</details>`（見出しを省くと「詳細」） |
| コードのファイル名 | ```` ```js:foo.js ````、```` ```:foo.txt ```` | `<figure><figcaption>foo.js</figcaption><pre>…</pre></figure>` |
| diff と言語の色分け | ```` ```diff js ````、```` ```diff js:foo.js ```` | 行に追加と削除のクラスを付け、言語の色分けをする |
| 数式のブロック | `$$` 〜 `$$` | KaTeX で描画する |
| インラインの数式 | `$a \ne 0$` | KaTeX で描画する |
| 図 | 言語名を `mermaid` にしたコードブロック | mermaid で描画した SVG |
| 画像の幅 | `![説明](URL =250x)` | `<img width="250">` |
| 画像の説明 | 画像の直後の行に `*説明*` | CSS で画像の下に小さく表示する |
| インラインの脚注 | `^[内容]` | GFM の脚注と同じ参照と定義 |
| リンクカード | URL だけの段落 | ホスト名と URL を枠で囲んだリンク |

### 自前で書くもの、ライブラリを使うもの

記法の解析と変換は自前で書く（`web/src/markdown/`）。
remark-math、remark-directive、rehype-katex などは使わない。依存を増やさないためと、記法の細部を Zenn に合わせるためである。
描画には、再実装が現実的でない KaTeX（数式）と mermaid（図）だけを使う。

- **`:::` と `$$`**：micromark の構文拡張として、コードブロック（```` ``` ````）と同じ規則のフェンスを書く（`web/src/markdown/fence.ts`）。閉じのフェンスは開き以上の長さのものだけで、閉じがなければ文書の終わりまでが中身になる。リストの項目の中にも書け、段落の直後にも書ける。
- **`:::` の中身**：加工せずに取り出し、Markdown として読み直す。Zenn が使う markdown-it-container と同じく、外側と同じ長さの `:::` は外側を閉じるので、入れ子にするには外側のコロンを増やす。
- **インラインの数式**：micromark の構文拡張で読む。金額の `$` を数式にしないよう、markdown-it-katex と同じ規則にする。開きの `$` の直後が空白でないこと、開きの後の最初の `$` が閉じであること、閉じの直前が空白でなく直後が数字でないことを求める。改行はまたがない。
- **コードの情報文字列、インラインの脚注、画像の幅、リンクカード**：構文木（mdast）を書き換える。画像の幅は、CommonMark では URL の後の ` =250x` のせいで画像として読まれずに文字列として残る。URL が `https://` で始まると GFM の自動リンクになるので、文字列、リンク、文字列の並びも読む。
- **diff と言語の色分け**：Shiki の前に通す rehype のプラグインで、各行の先頭の記号（`+`、`-`、`>`、`<`、空白）を外して言語の色分けを付け、記号を戻して行にクラスを付ける。記号で始まらない行（`@@` など）は、Zenn と同じく色を付けない。知らない言語なら diff の色分けだけを付ける。
- **画像の説明**：Zenn と同じく CSS（`img + em`）だけで表示する。

### 非同期の読み込み

KaTeX と mermaid は、Shiki（ADR 0017）と同じく本体とは別のチャンクにし、数式や図を描くときに初めて読み込む。
数式や図のないページでは読み込まない。
読み込むまでは、数式は TeX の文字列、図は mermaid の文字列をコードとして表示する。

| ライブラリ | 大きさ（圧縮前） |
|---|---:|
| KaTeX | JS 約 259 KB、CSS 約 27 KB、フォント（woff2）約 292 KB |
| mermaid（フローチャート 1 つを描くとき） | 約 2.2 MB |

KaTeX の CSS は woff2、woff、ttf の 3 形式のフォントを参照している。
対応するブラウザはすべて woff2 を読めるので、ビルドの設定（`web/vite.config.ts`）で woff と ttf の指定を外し、出力から除く（約 876 KB 減る）。

書き誤りのある数式は、TeX の文字列と「（数式を解釈できませんでした）」を表示する。
書き誤りのある図は、「図を描画できませんでした。」と図の文字列を表示する。
どちらもコンソールにエラーを出さない（出すと Lighthouse のベストプラクティスが下がる、ADR 0024）。

mermaid は `securityLevel: "strict"` で使い、図の中のクリックの処理や HTML を許さない（Zenn と同じ）。
テーマは白黒の `neutral` にする。

### sanitize との兼ね合い

拡張が作る要素も sanitize（ADR 0018）を通る。
許可一覧に `div`、`span`、`figure`、`figcaption` を足し、`div` と `span` は拡張が付けるクラス（`message`、`message-alert`、`math-display`、`math-inline`、`link-card-host`、`link-card-url`）と `role="note"` だけを残す。
sanitize の後に、クラスを持たない `div` と `span` のタグを外すので、本文に HTML で書いた `div` と `span` はこれまでどおりタグだけが外れる。
本文に HTML で同じクラスを書くと、拡張と同じ見た目になる。見た目が同じになるだけで害はないので許す。

### 見た目

- メッセージは薄い黄色の枠、警告は薄い赤の太い枠にし、左に「!」の印を付ける。色だけで区別しないよう、警告は枠を太くする。印は読み上げない。
- コードのファイル名は、コードの上に灰色の札として表示する。
- diff の行は、追加を薄い緑（`#e6ffec`）、削除を薄い赤（`#fff0f0`）の背景にする。テーマの文字色がすべて、これらの背景に対しても 4.5:1 以上になることをテストで確かめる。
- リンクカードは枠で囲み、ホスト名を太字で、URL をその下に表示する。

## 実装しないこと

- **`@` で始まる埋め込み**（`@[gist]`、`@[codepen]`、`@[speakerdeck]` など）。依頼の対象外。
- **リンクカードの題名、説明、画像**。ブラウザからはほかのサイトの HTML を読めない（CORS）。ビルド時に CLI で取得すればできるが、ビルドがネットワークと相手のサイトに依存するので、別に決める。
- **X（Twitter）、YouTube、GitHub の埋め込み**。それぞれの URL だけの行も、ほかの URL と同じリンクカードにする。埋め込むには `iframe` や外部のスクリプトが要り、許可しないタグ（ADR 0018）に当たるうえ、外部への通信と第三者の Cookie でベストプラクティスの 100 点（ADR 0024）を保てなくなる。
- **mermaid の文字数と `&` の数の制限**。Zenn はサーバーと閲覧者の負荷のために制限しているが、ここでは書き手が自分のサイトに載せる図なので制限しない。
- **絵文字の入力補完**。Zenn の編集画面の機能で、記法ではない。
- **mermaid が使う KaTeX の共有**。mermaid 12 は KaTeX 0.16 に依存し、図のラベルに数式を書いたときだけ読み込む。数式には最新の 0.18 を使うので、ビルドの出力に 2 つの版が入る（約 259 KB）。mermaid に 0.18 を使わせると互換性を確かめる必要があるので、そのままにする。

## テスト設計

vitest で、本文の描画結果を検証する（`web/src/markdown/extensions.test.tsx`）。

- `:::`：メッセージ、警告、見出しのある折りたたみとない折りたたみ、中身の Markdown（リスト、コードブロック）、コロンを増やした入れ子、同じ長さの `:::` が外側を閉じること、リストの項目の中、段落の直後、閉じのないもの、知らない名前とコロンの足りないもの（段落のまま）。
- 数式：ブロックとインラインを取り出すこと、金額の `$`、空白で始まるもの、`\$`、コードの中の `$` を数式にしないこと、`$$` の行に式を書いたものをブロックにしないこと。KaTeX を読み込んだ後に MathML 付きで描画すること、書き誤りを日本語の説明と一緒に表示すること。
- コード：情報文字列の読み方、ファイル名の figure、diff と言語の行のクラスと記号と色、知らない言語の diff、mermaid のブロックに色を付けないこと。
- インラインの脚注：GFM の脚注と合わせた番号、強調とリンクと括弧を含む内容、書き手の脚注の名前と重ならないこと、閉じのないもの。
- 画像の幅：サイト内と外部の URL、リンクの中の画像、形の違うもの、画像の直後の強調。
- リンクカード：URL だけの段落と `<URL>`、文中の URL、リンク文字列のあるリンク、`www.` で始まるもの。
- sanitize：クラスを持たない `div` と `span` のタグを外すこと、拡張と同じクラスは残すこと。
- テーマの文字色が diff の行の背景色に対しても 4.5:1 以上であること。

見本の記事 `example/content/articles/extensions.md` に全部の記法を載せ、Lighthouse の計測するページに加えた。
アクセシビリティとベストプラクティスは 100 点だった。
ブラウザでは、メッセージ、入れ子の折りたたみの開閉、ファイル名、diff の色、数式、図、画像の幅と説明、リンクカードの表示を確認した。

## トレードオフ

- 利用者向けのバイナリに埋め込む SPA が、約 2.3 MB から約 8.0 MB になる。ほとんどが mermaid とその依存である。
- 図のあるページは、読み込む量が大きく増える（mermaid だけで約 2.2 MB）。Lighthouse のパフォーマンスは、見本の記事で 42 点だった。
- `:::` の中身は別の文書として読み直すので、外側に書いた脚注やリンクの定義を中から参照できない。
- Zenn と違う記法（Markdown の方言）なので、ほかのサービスに記事を移すと、これらの記法はそのまま文字として出る。
