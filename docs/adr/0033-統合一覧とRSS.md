# 0033 統合一覧と RSS

## 状態

提案（利用者の確認待ち）。
仕様書の未決事項「種別をまたいだ統合一覧と RSS」に答える。

## 決定

### 統合一覧

`/archive` に、post と article をまとめた一覧（「すべての記事」）を置き、ヘッダに「一覧」の案内を足す。

- 日付の新しい順に並べ、年ごとの見出しで区切る。
- 同じ日付なら article を先に、slug の逆順にする。
- 各項目に日付、題名、種別（ブログ、記事）、article なら要約を出す。
- トップページの、種別ごとの一覧はそのまま残す。

一覧は DB の `posts` と `articles` を `UNION ALL` で合わせて引く（`listAll`）。DB の形は変えない。

### RSS

`site.toml` に `url`（公開したサイトの URL）を足す。
`url` を書くと、`build`、`serve`、`deploy` が RSS 2.0 のフィード `/rss.xml` を作る。

- フィードの中のリンクは絶対 URL である必要がある。公開先の URL は CLI からは分からない（Cloudflare の workers.dev、GitHub Pages、独自ドメイン）ので、書いてもらう。書かなければフィードを作らない。
- `url` は `http://` か `https://` で始め、末尾の `/` は補う。クエリやフラグメントは使えない。
- `url` のパスは `base_path`（ADR 0030）と同じにする。違えばエラーにする。フィードのリンクと、サイトを置くパスを食い違わせないためである。
- 形式は RSS 2.0 にする。依頼が RSS であり、ほとんどの読み手が読める。`atom:link rel="self"` も入れる。

フィードの中身は次のとおり。

- チャンネル：サイト名、`url`、サイトの説明（`description`、ADR 0022）、`ja`、最新の項目の日付。
- 項目：post と article を日付の新しい順に 20 件。題名、リンク、`guid`（リンクと同じ）、`pubDate`、説明。
- 説明は、article の要約か、なければ本文の書き出し（Markdown の記号、コードブロック、HTML のタグを大まかに取り除いた 120 文字）。本文は載せない。CLI は Markdown を HTML にしない（ブラウザが描く、ADR 0007）ので、フィードのために変換を持つと、表示とずれる。
- `pubDate` はその日の 0 時とする。`timezone` を時差（`+09:00` など）で書いたときはその時差を、名前（`Asia/Tokyo`）で書いたときと書かないときは `+0000` を使う。名前から時差を求めるには、日付ごとのタイムゾーンの規則を読む必要があるためである。日付は変わらない。

フィードの案内として、`index.html`（と `404.html`）の head に `<link rel="alternate" type="application/rss+xml">` を入れる。
SPA はこの案内があるときだけ、フッターに RSS のリンクを出す。DB にフィードの有無を持たせずに済む。

見本の `site.toml` に、公開している見本の URL を `url` として書く。

## 実装しないこと

- フィードに本文を載せること。
- Atom 形式のフィード。
- 種別ごとのフィード。
- 名前で指定したタイムゾーンの時差を `pubDate` に使うこと。
- 一覧のページ送り。記事が増えて一覧が長くなったら考える。

## テスト設計

- 項目：post と article を日付の新しい順に合わせ、同じ日付ならパスの逆順、20 件に切ること。article の要約と、なければ本文の書き出しを使うこと。
- 本文の書き出し：見出し、強調、リンクと画像の URL、HTML のタグ、コードブロック、箇条書き、コンテナの記号を取り除き、120 文字で切ること。
- 日付：RFC 822 の形（曜日、うるう年、負の時差）。
- フィード：サイト名などの文字の実体参照、絶対 URL のリンクと `guid`、`atom:link`、最新の日付。
- `url` の補い方と、不正な形（スキームなし、http 以外、ホストなし、クエリ、空白）、`base_path` と食い違うときのエラー。
- 組み立て：`url` を書いたときだけ `/rss.xml` を作り、`index.html` と `404.html` に案内を入れること。
- SPA：`listAll` の並び。
- 結合テスト：見本をビルドすると `rss.xml` ができること。

見本をビルドした `rss.xml` を XML として読めることを確かめた。
ブラウザでは、`/archive` の年の見出しと項目、フッターの RSS のリンクを確かめた。

## トレードオフ

- `url` を書かないとフィードができない。
- `url` を書いた後に公開先を変えたら、`url` も書き換える必要がある。
- フィードの説明は書き出しだけなので、フィードの読み手で本文は読めない。
