# 0004 コンテンツ種別と固定ページ

## 状態

採用。0001 の「記事は単一種別」という前提を拡張する。

## 決定

コンテンツを三種別に分け、`content/` 以下のディレクトリで区別する。

- **post**（`content/posts/`）：ブログ的な軽量の記事。日付とタイトルだけを持つ。
- **article**（`content/articles/`）：独立した読み物。post に加えて `description`（一覧に出す要約）と `updated`（改稿日）を任意で持つ。
- **page**（`content/pages/`）：自己紹介などの固定ページ。日付を持たない。

### frontmatter

| キー | post | article | page |
|---|---|---|---|
| `title` | 必須 | 必須 | 必須 |
| `date` | 必須 | 必須 | なし |
| `description` | なし | 任意 | なし |
| `updated` | なし | 任意 | なし |

### スキーマ

`posts`、`articles`、`pages` の三テーブル。定義は ADR 0005 のマイグレーションに置く。

### ルーティング

- `/`：トップページ。導入の一文、article 一覧（title、description、date）、post 一覧（date、title）を置く。
- `/posts/:slug`、`/articles/:slug`：本文。article は改稿日があれば併記する。
- `/about`：`pages` の slug `about` を表示する。ヘッダのナビに置く。

旧 `/articles/:slug` は blog 記事の URL だったが、デプロイ前のため互換は考慮しない。

## 実装しないこと

- 種別をまたいだ統合一覧と RSS。必要になった時点で ADR を追加する。
- page の複数ナビ管理。ナビはトップと自己紹介の二つを固定で持つ。

## テスト設計

- 種別ごとの frontmatter 検証（article の `description` が一覧クエリで返る、page が日付なしで通る）を vitest に追加する。
- 三種別を含むフィクスチャから DB を生成し、各テーブルの行を検証する。

## トレードオフ

- post と article の境界は書き手の判断に委ねる。機械的な基準（文字数など）を設けても運用が形骸化するためである。
