# 0045 図のレイアウトのずれ

## 状態

提案。
0044 の E2E の「レイアウトがずれない」から、図の多い記事（`/articles/heavy-diagrams`）を外す。

## 決定

図（mermaid）は、描く前（図の文字列をコードとして表示したもの）と描いた後で高さが変わる。
図が最初の画面にあると、その下の本文が押し下げられ、レイアウトがずれる。
数式で起きている問題（0040）と同じ種類で、まだ直していない。

0044 の E2E は、手元の macOS では図の多い記事でもずれなかった（最初の画面に図が入らなかった）が、GitHub Actions の Linux ではずれた（0.002）。
フォントの違いで行の折り返しが変わり、最初の画面に図が入ったためと考えている（確かめてはいない）。
この失敗で、v0.1.1 の最初のリリースのワークフローは E2E で止まり、Release は作られなかった。

図の多い記事を、数式でずれる既知の記事と同じく、E2E のずれを確かめる対象から外す。
ほかの確認（エラーなく描かれること、図の数、elk の読み込み）は続ける。

## 実装しないこと

- 図を描く前の高さを、描いた後の高さに合わせて取っておくこと。図の高さは描くまでわからない。0040 の数式と合わせて、別に考える。

## テスト設計

- E2E を手元で動かし、すべて成功することを確かめた。
- GitHub Actions の CI とリリースのワークフローで、E2E が成功することを確かめる。

## トレードオフ

- 図の多い記事で、レイアウトのずれが増えても E2E では気付けない。Lighthouse の Cumulative Layout Shift の記録で見る。
