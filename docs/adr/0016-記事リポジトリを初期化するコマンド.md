# 0016 記事リポジトリを初期化するコマンド

## 状態

採用。
あわせて、0007 の「本文中の生の HTML は描画しない」の実装の誤りを直す（後述）。

## 決定

CLI に `init` を足し、ビルドに必要なファイルとディレクトリを作る。

```
sqlite-cms init [SITE_DIR] [--title <TITLE>] [--force]
```

### 作るもの

```
site.toml                  -- title だけを有効にし、ほかの設定はコメントで例を示す
content/index.md           -- トップページの本文。表示されないコメントだけを入れる
content/pages/about.md     -- 自己紹介（ヘッダのリンク先。ないとリンク先が「見つかりません」になる）
content/posts/.gitkeep
content/articles/.gitkeep
content/media/.gitkeep
```

- `SITE_DIR` がなければ作る。`sqlite-cms init my-blog` で新しい記事リポジトリを作れる。
- `title` は `--title` で指定し、省略するとディレクトリ名にする。toml クレートで書き出すので、`"` や改行を含んでいても正しく引用される。
- 空のディレクトリには `.gitkeep` を置き、git で追跡されるようにする。ビルダーは `.md` 以外を読まず、`media/` のドットファイルは配信しないので、`.gitkeep` がサイトに出ることはない。
- 本文は空にする（ADR 0015 と同じ理由）。

### 既存のファイルとの関係

- `site.toml` か `content/` がすでにあれば、何も作らずにエラーにする。どちらがあるかをメッセージに示す。
- `--force` を付けると、上の一式を作り直す。`site.toml`、`content/index.md`、`content/pages/about.md` は上書きし、どれを上書きしたかを表示する。
- `--force` でも、`init` が作るもの以外（記事、画像など）は消さない。「強制的に初期化する」を、書いた記事まで消すことだとは解釈しない。記事を失うと取り戻せないためである。まっさらにしたいときは、`content/` を自分で消してから `init` を実行する。
- `init` が作るファイルの場所にディレクトリがあるときは、`--force` でもエラーにする。

### 生の HTML の表示の修正

`init` が作る `index.md` の HTML コメントがトップページに文字として表示されたことで、次の不具合が分かった。

react-markdown は、既定の設定では生の HTML を要素にはしないが、エスケープした文字列として表示する。
0007 と README は「本文中の生の HTML は表示されない」としていたが、実際には文字として表示されていた。
これまでのテストは「`<script>` という要素にならないこと」しか確かめておらず、この表示を見逃していた。

react-markdown の `skipHtml` を有効にし、生の HTML（コメントを含む）を表示しないようにする。
テストは、生の HTML が要素にも文字にもならないこと（`alert(1)` や `&lt;` が出力に含まれないこと）まで確かめる形に改める。
このテストが修正前のコードで失敗することも確認した。

## 実装しないこと

- 記事リポジトリ用の公開ワークフロー（`example/.github/workflows/deploy.yml`）の自動生成。公開の方法は人によって違うので、README の手順でコピーする。
- `.gitignore` の生成。記事リポジトリにはすでに `.gitignore` があることが多く、上書きや追記の扱いが複雑になる。`build` の出力先（既定の `dist/`）を除外するかは、書き手が決める。
- 対話的な質問（サイト名や公開先を尋ねるなど）。

## テスト設計

- 引数の解釈：既定値、`--title` と `--force`、余分な引数、`init` で使えないオプション、ほかのコマンドでの `--force`。
- 初期化：作るファイルの一覧、作った `site.toml` の解釈、そのまま DB を組み立てられること、`.gitkeep` が配信物に入らないこと、どんなタイトルでも `site.toml` から元に戻ること。
- 既存のファイル：`site.toml` や `content/` があるとエラーになり何も変えないこと、`--force` で `init` のファイルを作り直しつつ記事と画像を残すこと、空のタイトル、ディレクトリでない `SITE_DIR`。
- 結合テスト：`init` → `new` → `build` がそのまま通ること（最初に使うときの流れ）、`--force` なしで止まり、ありで上書きすること。
- SPA：生の HTML（`<script>`、インラインの要素、コメント）が要素にも文字にもならないこと。

## トレードオフ

- `--force` は記事を消さないので、「完全に初期状態に戻す」用途には使えない。取り返しのつかない削除を CLI のオプション一つでできるようにするより、利用者が自分で消すほうが安全である。
- `skipHtml` によって、本文中の `<br>` のようなインラインの HTML も表示されなくなる。これは 0007 で決めた方針どおりである。
