# 0036 ADR 0031、0033、0034 の機能の統合

## 状態

提案（利用者の確認待ち）。
ADR 0031、0033、0034 は、それぞれ main から分けたブランチで実装した。
この ADR は、それらを一つにまとめたとき（ブランチ `integration/all`）に、組み合わせで決めたことを記録する。

## 番号について

0032（プレーンテキストの記事）と 0035（ページごとの HTML と OGP）は、同じときに案を作ったが、取り下げた。

- 0032：golem の仕様が固まっていないので、取り込む形式を決めるのは早い。
- 0035：ページごとに HTML を作ると、生成するファイルが記事の数だけ増える。ほかの方法を考える。

どちらのブランチも消し、この統合にも入れていない。0032 と 0035 の番号は使わない（欠番）。
仕様書の未決事項には、二つとも残し、案を作って保留したことを書き添える。

## 決定

### ヘッダの案内

- ヘッダの案内は「トップ」「一覧」（0033）「自己紹介」「検索」（0031）の順にする。
- 案内が四つになり、スマートフォンの幅ではサイト名と一行に収まらなくなった。サイト名は DB を読んだ後に入るので、そのときに案内が折り返してヘッダが高くなり、本文が下にずれた（Lighthouse の CLS が 0.80、パフォーマンスが約 20 点下がった）。
- 狭い画面（Tailwind の `sm` 未満）ではサイト名と案内を別の行にし、ヘッダの高さを変えないようにする。

### その他

- Lighthouse の計測するページは、0031 の検索と 0033 の一覧を合わせて 8 ページにする。
- 計測では、0034 の `--no-reload` で `serve` を起動する。
- 仕様書の未決事項から、0031、0033、0034 で対応した三つの項目を外す。
- 0033 の RSS は、0034 の自動反映で組み立て直すたびに作り直される。
- マイグレーションは足していない。

## テスト設計

各ブランチのテストは、統合した後もすべて通ることを確かめた。
Lighthouse で、スマートフォンの幅の CLS が小さくなり、点数が各ブランチと同じくらいに戻ることを確かめた。

## トレードオフ

- 三つのブランチを別々にマージすると、ヘッダの修正は入らない。検索（0031）と一覧（0033）の両方を入れるときは、同じように直す必要がある。
