# 0061 ページごとの OGP

## 状態

破棄。
試作したが採らない。試作は、ブランチ `feat/ogp`（コミット 2d196f9）に残す。

## 背景

X、Facebook、Slack、Discord などのリンクの展開（OGP を読むもの）は、JS を動かさない。
sqlite-cms は、すべてのページで同じ `index.html` を返し、題と説明はページを開いた後に SPA が入れる。
そのため、展開には題も説明も届かない（`<title>` も空で、OGP のメタタグはない）。

## 試したこと

ビルドのときに、ページごとに `index.html` の写しを作り、題と説明と OGP を入れる形を試した。画像は使わない。

- 作るページ：トップ（`index.html` そのもの）、post、article、カテゴリ、自己紹介。
- 入れるもの：`<title>`（SPA と同じ `<題> - <サイト名>`）、`description`、`og:type`（記事は `article`、ほかは `website`）、`og:site_name`、`og:title`、`og:description`、`og:url`（site.toml に `url` があるとき）、`twitter:card`（`summary`）。`og:image` は入れない。
- 説明：article とカテゴリは `description`、なければ本文の書き出し（RSS の要約と同じ処理）。post と自己紹介は本文の書き出し。
- 置き場所：`/<パス>.html`（`/articles/syntax.html`）。Cloudflare と GitHub Pages は、`/<パス>` への要求にこのファイルを返す。`serve` も同じにした。
- カテゴリのページの HTML（`/<slug>.html`）がほかのファイルと重ならないよう、カテゴリに使えない slug に `index`、`404`、`mermaid-frame` を足した。

手元のテスト、E2E、Lighthouse、Core Web Vitals は通った。

## 採らない理由

試作を見て、採らないと決めた。試作で見えた問題は次のとおり。

- 説明に使う本文の書き出しが、文中のコード（`` `<ruby>` `` など）を取り除くので、文が欠ける（RSS の要約も同じ）。
- post の説明が、HTML（本文の書き出し）と、SPA が開いた後に入れるもの（サイトの説明）で食い違う。
- ページの数だけ HTML が増える（見本で 19 ページ、1 ページあたり gzip 後で約 5 KB）。
- rsync の送り先では、サーバーに `.html` を探す設定（nginx の `try_files $uri $uri.html …` など）が要る。
- Cloudflare が `/<パス>` に `/<パス>.html` を返すことと、各サービスでの表示は、公開して確かめていない。

## 今後

ページごとの OGP が要るようになったら、この試作から始める。そのときは、少なくとも次を考える。

- 記事ごとの画像（`og:image`）を作るか、サイト全体で一枚の既定の画像を使うか。
- 説明の書き出しで、文中のコードを残すこと。
- SPA の meta description を、HTML と同じ規則にそろえること。
