# 0017 Shiki によるシンタックスハイライト

## 状態

採用。
0038 で、`@shikijs/rehype` をやめ、コードブロックの部品がブロックごとに色分けする形に改めた。
0046 で、正規表現エンジンを Oniguruma（wasm）にし、色分けを Web Worker の中で行うことにした。

## 決定

本文のコードブロックに、Shiki（`shiki`、`@shikijs/rehype`）で色を付ける。

### 選定

unified 系の候補（rehype-highlight、rehype-prism-plus、rehype-starry-night、@shikijs/rehype）を比べ、Shiki にした。
決め手は次の三点である。

- **正確さ**：VS Code と同じ TextMate の文法定義を使う。同じ TypeScript の型定義で、highlight.js の 4 個に対して 22 個の区切りで色を分けた。
- **CSS が要らない**：テーマの色がインラインで入る。
- **開発が活発**：2026 年 8 月にも更新がある。

ほかの候補を選ばなかった理由は次のとおり。

- rehype-highlight（highlight.js）と rehype-prism-plus（Prism）は、同じ言語数なら 5 分の 1 ほどの大きさで済むが、正規表現ベースで色分けが粗い。
- rehype-starry-night は正確さでは同等だが、非同期でしか動かない。さらにブラウザでは既定で、正規表現エンジンの wasm を外部の CDN（esm.sh）から実行時に取りに行く。

### 組み込み方

- wasm を使わない JavaScript の正規表現エンジン（`shiki/engine/javascript`）と `createHighlighterCoreSync` で、ハイライタを同期的に作る。
- `@shikijs/rehype/core` の `rehypeShikiFromHighlighter` を react-markdown の `rehypePlugins` に渡す。事前に作ったハイライタを使い、`lazy` を使わなければ変換は同期的に終わるので、同期的な `Markdown` コンポーネントのまま使える。
- ハイライタは一度だけ作り、使い回す（作成は数ミリ秒）。
- 言語とテーマは `@shikijs/langs/<言語>`、`@shikijs/themes/<テーマ>` から個別に読み込み、使うものだけをバンドルに入れる。どちらも shiki と同じ版を直接の依存として明示する。

### 言語とテーマ

- 登録する言語：CSS、diff、Haskell、HTML、JavaScript、JSON、Markdown、Python、Rust、シェル、SQL、TOML、TSX、TypeScript、YAML。
  - 各言語の別名（`ts`、`sh`、`hs`、`yml` など）もそのまま使える。
  - JSX は TSX の定義で色を付ける（`langAlias`）。JSX 用の定義（gzip 後で約 16 KB）を入れずに済む。
- 登録していない言語と、言語名のないコードブロックは、これまでどおり色なしで表示する。行内のコードには色を付けない。
- テーマは白背景に合う `github-light` にする。テーマの背景色（`#fff`）を `colorReplacements` で本文の `pre` と同じ `#f5f5f5` に置き換え、色付きのブロックと色なしのブロックの見た目を揃える。CSS は足さない。

### 非同期での読み込み

Shiki は gzip 後で約 162 KB（圧縮前で約 1,070 KB）あり、そのまま本体に入れると本体の JS が約 131 KB から約 293 KB に増える。
内訳は、Shiki の本体と JavaScript の正規表現エンジン、15 言語の文法定義である（言語ごとに gzip 後で 1〜16 KB）。
そこで、Shiki とその設定（`web/src/highlight.ts`）を `import()` で別のチャンクにし、非同期で読み込む。

- 本体のコードは Shiki を静的に参照しない。読み込みは `web/src/highlightLoader.ts` がまとめる。
- アプリの起動と同時に、DB の取得と並行して読み込み始める。多くの場合、記事を表示するまでに読み込みが終わる。
- 読み込みが終わる前に描画したコードブロックは色なしで表示し、読み込みが終わったら色を付けて描き直す。背景色、余白、書体は色なしのブロックと揃えてあるので、描き直してもレイアウトは動かない。
- 同時に何度呼ばれても読み込みは一度だけにする。読み込みに失敗したら色なしのまま表示を続け、次に本文を描画するときに読み込み直す。

本体の JS は gzip 後で約 132 KB のままで、Shiki のチャンクは初回の表示を待たせない。
vite の `chunkSizeWarningLimit` は、最も大きい Shiki のチャンクの少し上の 1,100 kB にする。意図しない増加に気付けるようにするためである。

## 実装しないこと

- 記事にコードブロックがあるときだけ Shiki を読み込むこと。起動時に並行して読み込むほうが、色が付くまでの待ちが短く、仕組みも単純である。
- 行番号、行の強調、コードブロックの題名（`meta` の解釈）。
- ダークモード用の二つ目のテーマ（仕様でダークモードを持たない）。
- 登録していない言語をその場で読み込むこと（`lazy`）。非同期になり、同期的な `Markdown` と両立しない。

## テスト設計

vitest で、本文の描画結果（`react-dom/server`）を検証する。

- 登録した言語と、テストの見本の言語が一致すること。言語を足したら見本も足さないとテストが落ちる。
- 登録した各言語が、複数の色に分かれること。枠だけ付いて中身が色分けされていない状態を見逃さないため。
- 色分けしても、コードの文字列が変わらないこと。
- 別名（`ts`、`js`、`jsx`、`sh`、`bash`、`zsh`、`shell`、`hs`、`yml`、`md`、`py`）でも色が付くこと。
- 背景色が `#f5f5f5` に置き換わること。
- 登録していない言語と言語名のないブロックは、従来と同じ HTML になること。行内のコードには色を付けないこと。
- コードブロックの中の `<script>` が要素にならず、文字として表示されること。
- ハイライタが一度だけ作られること。
- 読み込みの制御：読み込み前は何も返さず、読み込み後は結果を返すこと。同時に呼んでも読み込みが一度だけであること。失敗したら次の呼び出しで読み込み直すこと。
- 読み込み前は色なし、読み込み後は色付きで描画されること。

`example/content/posts/syntax-highlight.md` に、各言語と色なしのブロックの見本を置き、ブラウザで表示を確かめる。
Shiki のチャンクを 2 秒遅らせて返す中継サーバを通し、記事が色なしで先に表示され、読み込み後に色が付くこと、その前後でコードブロックの高さが変わらないことを確かめた。

## トレードオフ

- 読み込み全体の量は Shiki の分（gzip 後で約 162 KB）増える。非同期にしたので初回の表示は待たせないが、通信の遅い環境では、コードブロックに色が付くまで少し間が空く。
- JavaScript の正規表現エンジンは、一部の文法に対応しないことがある。登録した 15 言語は、テストの見本で動くことを確かめている。言語を足すときは、テストで同じことを確かめる。
- 登録していない言語は色が付かない。記事を書く人は、README の対応表を見る必要がある。
