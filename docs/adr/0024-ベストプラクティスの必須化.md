# 0024 ベストプラクティスの必須化

## 状態

採用。
0019 の「ベストプラクティスは計測して記録するだけ」を改める。

## 決定

Lighthouse のベストプラクティスも 100 点を必須とし、下回れば計測のスクリプトを失敗させる。
CI（`ci.yml`）も、リリースのビルド（`release.yml`、ADR 0021）も失敗し、Release は作られない。

favicon を配信するようにした（ADR 0022）ことで、すべてのページが 100 点になった。
ベストプラクティスで引かれるのは、コンソールのエラー、存在しないファイルの取得（404）、非推奨の API の使用などで、どれも気づかないうちに入り込む。
点数が下がったときにすぐ気づけるよう、基準にする。

### 失敗したときの表示

失敗したときは、アクセシビリティと同じく、点数を引いた監査を表示する。
重みが 0 の監査は表示しない。
たとえば「大きな JS にソースマップがない」はベストプラクティスに含まれるが、点数に影響しないので、原因と取り違えないようにする。

## 実装しないこと

- パフォーマンスと SEO の基準。SEO はすべてのページで 100 点だが、重視しないので基準にしない。

## テスト設計

- 本体の JS に `console.error` を一時的に足して計測し、全ページが 96 点になって、終了コード 1 で終わり、「コンソールにエラーが出た」監査だけが表示されることを確認した。

## トレードオフ

- コンソールに一度でもエラーが出ると CI が失敗する。計測の間に一時的な通信の失敗が起きても失敗する。
