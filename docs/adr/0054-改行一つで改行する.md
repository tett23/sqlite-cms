# 0054 改行一つで改行する

## 状態

提案。
0007 の「CommonMark と GFM に従って描く」に、段落の中の改行の扱いを足す。

## 決定

段落の中の改行一つを、空白ではなく改行（`<br>`）にする。Zenn と同じ扱いである。段落を分けるのは、今までどおり空行。

CommonMark では、段落の中の改行（soft line break）は空白と同じに扱われ、ブラウザでは文の間に空きが入る。日本語の文章では、改行で文を分けて書くことが多く（一文一行）、書いたとおりに行を分けるほうが、書き手の意図に合う。

- 自前の remark の変換（`web/src/markdown/transforms.ts` の `transformLineBreaks`）で、文字列の中の改行を `break` の節に分ける。改行の前後の空白は取り除く。remark-breaks は入れない（依存の方針）。
- 文字列の節だけを分けるので、コード（`code`、`inlineCode`）と数式の中の改行は変わらない。
- 行末の二つの空白や `\` による改行（hard line break）は、今までどおり一つの改行になる。
- 変換は、ほかの変換（インラインの脚注、画像の幅、リンクカード）の後に行う。インラインの脚注 `^[…]` は改行をまたいで書ける。
- 画像の直後の行の強調（画像の説明、0025）とのあいだには改行を入れない。説明は CSS の `img + em` で表示するので、あいだに `<br>` があると説明として表示されない。
- 本文だけでなく、トップページの本文とヘッダ（`content/header.md`）にも効く。

見本の記事は一文一行で書いているので、文が一つずつ行に分かれて表示される。

## 実装しないこと

- 改行一つで段落を分けること（`<p>` を分ける）。行の間に段落と同じ余白が入り、一文一行の文章では間延びする。
- 設定で切り替えること。記事リポジトリごとに記法が変わると、書き方の説明と見本が二通りになる。

## テスト設計

- 改行一つを `<br>` にし、空行で段落を分けること。改行の前後の空白を取り除くこと。行末の二つの空白と `\` の改行が一つの `<br>` のままであること。
- 強調、リンク、リスト、引用、`:::message` の中でも改行すること。
- コード、コードブロック、数式の中の改行はそのままであること。
- 改行をまたぐインラインの脚注を読むこと。
- 画像（と画像だけのリンク）の直後の行の強調とのあいだには改行を入れず、画像の後の強調でない行や、文の後の強調では改行すること。
- 知らない名前の `:::` の行（段落のまま）は、改行で分かれること（既存のテストを改めた）。

## トレードオフ

- 今までの記事で、段落の中で改行していたところは、表示が変わる（空白でつながっていた文が、行に分かれる）。
- CommonMark の記法とは違う扱いになる。ほかのツールで同じ Markdown を描くと、改行が空白になる。
